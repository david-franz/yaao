# F16.2 In-Session Capture

**Phase**: 15 — Session → Skill Distillation
**Priority**: High
**Dependencies**: F16.1

## Goal

Define how the calling agent's conversation reaches the distiller. The answer is uniform across every supported agent: the agent itself produces a structured self-summary of its session and hands it in as the distiller's `session` input. yaao never reads IDE-internal transcript stores (Claude Code's JSONL, Codex JSONL, Cursor's SQLite, Copilot's in-memory buffers). The agent is the source of truth for its own context.

This phase specifies the **contract** the agent must satisfy when producing that summary, the **MCP transport** that carries it (the `session` argument of `yaao_distill` — F16.4), and the **redaction** applied before the summary is handed off to the distiller's Stage 2 logic (F16.1).

## Why in-session only

Three reasons, in order of importance:

1. **Universality with no per-IDE work.** A native reader for Claude Code is easy; one for Cursor is a moving target tied to undocumented SQLite schemas; one for Copilot may not be possible at all. In-session works on day one for every agent that can call a tool.
2. **No "where is the truth?" ambiguity.** A reader and an in-session summary can disagree (transcript truncation, async flushing). With one path, there is one truth — the agent's own report.
3. **Active-session support is automatic.** Native readers can only see what has been flushed to disk. The most common use case — "distill what I just did" — is by definition still in-flight. In-session captures the live state.

The honest tradeoff: the summary is a self-report, not a recording. The distiller prompt (F16.1) compensates by requiring specific structural elements (verbatim user corrections, ordered final approach, tool calls + paths). Stage 2 generalization is robust to summary noise because it explicitly throws away instance-level detail anyway.

## The `SessionRecord` Contract

The agent produces a JSON object matching this shape, embedded inline in the `session` argument of `yaao_distill`:

```typescript
interface SessionRecord {
  /** Always 'in-session' in this phase. Reserved for future reader sources. */
  source: 'in-session';
  /** Optional human label for the session (e.g. "added widgets endpoint"). */
  label?: string;
  /** Ordered turns. */
  turns: SessionTurn[];
  /** Flat list of file paths the agent read or wrote during the session. */
  files: string[];
  /** Tool calls the agent made, in order. */
  tools: ToolCall[];
  /** Verbatim user corrections — short snippets where the user told the agent to change course. */
  corrections: string[];
}

interface SessionTurn {
  role: 'user' | 'assistant';
  /** Plain-text content. Agent should redact secret values it knows are sensitive. */
  text: string;
}

interface ToolCall {
  name: string;             // e.g. "Read", "Edit", "Bash"
  /** One-line summary of the args. Don't dump full file bodies. */
  argsSummary: string;
  /** 'ok' | 'error' | omitted if not relevant. */
  outcome?: string;
}
```

The shape is intentionally minimal. It captures **what was done** (turns, files, tools), **what was learned** (corrections), and **how to label it** (`label`). Anything richer (timestamps, token counts, full tool inputs) is dropped — the distiller doesn't use it, and it's a footgun for secret leakage.

## The Capture Instruction (lives in F16.1's prompt)

The distiller's prompt — already in the calling agent's context because the agent is the one invoking the tool — opens with a self-capture instruction. Roughly:

> Before generalizing, produce a structured summary of this conversation as a `SessionRecord` JSON object. Include: ordered user / assistant turns (text only, drop tool-call noise); the flat list of file paths you read or wrote; tool calls you made (name + one-line arg summary); and verbatim corrections the user gave you. Redact any secrets you can identify. Hand this back as the `session` input.

The agent's job is *report*, not edit. Generalization happens later in Stage 2 (F16.1).

## Transport

The `SessionRecord` reaches yaao as the `session` argument of the `yaao_distill` MCP tool (F16.4). There is no shell-CLI transport — distillation only exists as an MCP operation, because the agent producing the `SessionRecord` is by definition the agent calling the tool. See [PHASE-16.md](PHASE-16.md) for the rationale.

The argument is validated against a Zod schema mirroring the TypeScript types above before being handed to the distiller's Stage 2 (F16.1).

## Validation

Before handoff to the distiller (Stage 2 of F16.1), yaao validates the `SessionRecord`:

| Check | Failure mode |
| --- | --- |
| Zod schema match | `YAAO_SESSION_INVALID` with the issue path |
| `turns` non-empty | `YAAO_SESSION_EMPTY` |
| At least one `assistant` turn | `YAAO_SESSION_NO_AGENT_WORK` |
| Total `turns[].text` ≤ 256 KB | `YAAO_SESSION_TOO_LARGE` |
| Each `tools[].argsSummary` < 500 chars | `YAAO_SESSION_TOOL_ARG_BLOAT` |

These are guardrails against the two failure modes self-summaries exhibit in practice: empty summaries (agent didn't actually do the capture step) and bloated ones (agent pasted whole file bodies into `argsSummary`).

### Why 256 KB and not 64 KB

A realistic long-form session — ordered turns + verbatim corrections + tool calls + paths — easily exceeds 64 KB once it's been honestly captured. An earlier draft of this spec capped at 64 KB with a hint of "summarize further" — but **the distiller's job is to summarize**, so pushing pre-summarization onto the calling agent is the wrong split. 256 KB comfortably fits a multi-hour session with several files touched and a half-dozen corrections, while still being small enough that Stage 2 processing stays in a single agent turn. If a session genuinely exceeds 256 KB the user is almost certainly trying to distill two sessions at once and should split them — that's the error path `YAAO_SESSION_TOO_LARGE`'s hint points at.

## Redaction

The agent is asked to redact known secrets in its self-summary; yaao runs a second pass before handing off to Stage 2.

The existing yaao codebase only detects API keys at a specific JSON path (`agents.api.providers.<provider>.api-key`, via [config/loader.ts](../../src/config/loader.ts)) — it does **not** do general pattern-based secret detection today. F16.2's redaction pass is therefore net-new code, not a reuse of existing detectors. It lives in a new helper (`src/distill/redact.ts`) and is scoped to `SessionRecord` content only.

What it detects:

| Pattern | Source | Action |
| --- | --- | --- |
| `AKIA[0-9A-Z]{16}` | AWS access keys | replace value with `[REDACTED:aws]` |
| `ghp_[A-Za-z0-9]{36,}` / `github_pat_[A-Za-z0-9_]{20,}` | GitHub tokens | `[REDACTED:github]` |
| `sk-[A-Za-z0-9_-]{20,}` | OpenAI / Anthropic-style keys | `[REDACTED:llm]` |
| `xox[bpoa]-[A-Za-z0-9-]{10,}` | Slack tokens | `[REDACTED:slack]` |
| `(?:[A-Z][A-Z_0-9]+_(?:TOKEN\|KEY\|SECRET))=\S+` | env-style `FOO_TOKEN=…` assignments | redact the value, keep the env name |
| `${ENV_VAR}` references | yaao's own secret-injection syntax | leave the reference, strip any adjacent literal value |

Additionally:

- Any single literal in `turns[].text` longer than 4 KB is truncated to 200 chars + `[... truncated, N more chars]`. The distiller does not need long literal content; if a snippet is load-bearing, the agent should describe it, not paste it.

Redaction is applied to the in-memory record; the unredacted form is never persisted, logged, or returned in any response. The patterns above are intentionally tight — false positives would corrupt the captured session. A "scan and warn but don't redact" mode for ambiguous matches is a possible follow-up; not in v1.

## Acceptance Criteria

- A valid `SessionRecord` passed as the `yaao_distill` `session` argument is accepted and handed to F16.1 Stage 2 unchanged (except for redaction).
- A malformed `SessionRecord` fails Zod validation with a precise issue path.
- Empty `turns`, missing `assistant` turns, or oversized payloads each produce the right error code.
- A `SessionRecord` containing `sk-test_abcd1234` in any field arrives at Stage 2 with that value redacted.
