# F16.3 Context Handoff Enrichment

**Phase**: 15 — Concurrent Runs & Context Handoff
**Priority**: Medium
**Dependencies**: F5.3 (context passing)

## Goal

Make the parent→child handoff carry the meta-context a dependent agent
actually needs to reason about an upstream task, not just the file list and
an 80-line stdout tail. Today [src/exec/context.ts](../../src/exec/context.ts)
produces a `context.md` artifact with:

- task id + title
- parent branch
- file-changed totals + per-file status list
- last 80 lines of agent stdout (deduplicated)
- single head commit SHA + subject

The child's worktree branches off the parent, so the *code* is on disk. The
artifact's job is the supplementary meta-context. Four pieces are missing:

1. **The parent's task prompt** — the dependent has no record of what the
   parent was asked to do. Agents write terse stdout ("done") that's
   ambiguous without the prompt.
2. **The validation outcome** — already recorded on `task:completed`
   ([lifecycle.ts:464-473](../../src/exec/lifecycle.ts#L464-L473)) but
   dropped from the handoff. A test-task depending on an impl-task should
   know whether the impl-task's lint/typecheck passed.
3. **The full commit chain** — only the head subject is included
   ([context.ts:53](../../src/exec/context.ts#L53)). A parent that made
   three commits ("scaffold", "wire DI", "fix lint") shows only "fix lint".
4. **A per-file diff stat** — only the numstat totals. `git diff --stat`
   fits in the existing per-dep budget and gives the child a one-line shape
   per changed file.

## Design

### `context.md` shape (additive)

The existing sections stay. New sections are appended in this order so
existing readers (Stage 1 of any consumer prompt) don't shift:

```markdown
# <id> — <title>

**Branch**: <branch>
**Files changed**: N (+I / -D)

## Original task
<first 30 lines of the parent's resolved promptBody, then "(truncated)" if longer>

## Validation
<rendered only when validationOutcome is present on completion>
- Command: `<command>`
- Exit code: 0 (passed)  | N (failed, must-pass=<bool>)
- Duration: <ms>ms
- Decision: exit-code

## Summary
<existing last-80-lines tail>

## Diff
<`git diff --stat <baseBranch>...HEAD` output, capped at ~30 lines>

## Commits
<`git log <baseCommit>..HEAD --format="- %h %s"`>

## Files
<existing per-file status list>
```

All new sections are budget-friendly (parent prompt: ~30 lines cap; diff
stat: ~30 lines cap; commit chain: bounded by however many commits the
parent actually made). The per-dep token budget already trims aggressively
([context.ts:122](../../src/exec/context.ts#L122)); the new sections sit
inside the same cap.

### Plumbing

- `writeContextMd` in [src/exec/context.ts](../../src/exec/context.ts) takes
  three new fields on the `TaskOutcomeArtifact`:
  - `originalPrompt?: string` — resolved at completion time from the same
    `resolvePromptBody(...)` call the lifecycle already makes
    ([lifecycle.ts:191](../../src/exec/lifecycle.ts#L191)).
  - `validation?: { command, exitCode, durationMs, mustPass, decisionReason }`
    — passed through from `validationOutcome`.
  - `commits?: { sha: string; subject: string }[]` — emitted by a new
    `git log <baseCommit>..HEAD --format=%H%x00%s` call alongside the
    existing diff-stats fetch.
  - `diffStat?: string` — output of `git diff --stat <baseBranch>...HEAD`,
    trimmed to ~30 lines.
- `buildContextPrefix` is unchanged structurally; the new sections are
  inside the per-dep budget so the existing trimming logic just works.
- `Lifecycle.runTask` collects these fields just before `writeContextMd`
  is called ([lifecycle.ts:444-455](../../src/exec/lifecycle.ts#L444-L455))
  and threads them in.

### Opt-out

A per-plan toggle for users who want to keep the artifact lean:

```yaml
config:
  context:
    include: [prompt, validation, commits, diff]  # default: all four
```

`include: []` reproduces the pre-F16.3 artifact verbatim. Setting any subset
includes only those sections. Schema lives in
[src/plan/schema/plan.ts](../../src/plan/schema/plan.ts) under
`config.context` next to the existing `per-dep-budget` and `total-budget`.

## Acceptance criteria

- A task with a non-trivial prompt-ref produces a `context.md` whose
  `## Original task` section contains the first 30 lines of that prompt.
- A task with `validation.command` produces a `context.md` whose
  `## Validation` section contains the exit code, duration, and decision
  reason.
- A task that made N commits produces a `context.md` with N lines under
  `## Commits`, newest first.
- A task that changed M files produces a `## Diff` section with up to M
  lines (capped at 30) of `git diff --stat` output.
- `inherit-dep-context: false` on the child still skips the prefix entirely.
- `config.context.include: []` produces the pre-F16.3 artifact byte-for-byte
  on a small fixture, so existing prompts that hard-coded the old shape
  don't have to change unless the user opts in.
- Per-dep token budget caps are still respected when the new sections push
  a dep over its budget — existing `trimToTokenBudget` handles this; the
  test asserts the budget is the binding constraint.

## Tests

- `tests/phase-16/context/original-prompt-section.test.ts` — golden against
  a fixture with a 50-line prompt body; assert first 30 lines + truncation
  marker.
- `tests/phase-16/context/validation-section-passed.test.ts` — exit-code
  0, must-pass=true → `## Validation` records the verdict.
- `tests/phase-16/context/validation-section-absent.test.ts` — no
  validation command → `## Validation` is omitted entirely (no empty
  heading).
- `tests/phase-16/context/commit-chain.test.ts` — three commits on the
  task branch → three lines in `## Commits`.
- `tests/phase-16/context/diff-stat-cap.test.ts` — 60-file change → 30
  lines of `## Diff` + truncation marker.
- `tests/phase-16/context/include-opt-out.test.ts` — `include: []`
  reproduces the legacy artifact.
- `tests/phase-16/context/budget-trim.test.ts` — when a per-dep section
  exceeds the budget, it's trimmed at the existing budget cap and the
  truncation marker is present.
- `tests/phase-16/context/inherit-dep-context-false.test.ts` — the child
  with `inherit-dep-context: false` sees an empty prefix, unchanged from
  today.

## Out of scope

- Streaming the full tool-use trace or thinking blocks into the handoff.
  The journal + the web viewer activity stream remain the place to
  inspect a parent's full trajectory.
- A "structured diff" beyond `--stat`. Full hunks would blow the per-dep
  budget on any real-world task.
- LLM-summarized parent prompts. We include the first N lines verbatim;
  the dependent agent can summarize on its end if it wants to.
- Including the parent's `priorFailure` history (retry context) in the
  child's handoff. That's per-attempt internal state, not cross-task
  signal.
- Backfilling `context.md` artifacts for prior runs. The change is
  forward-only — `--resume` on an old run reads the old shape just fine
  because the new sections are additive.
