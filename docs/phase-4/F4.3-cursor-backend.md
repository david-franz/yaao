# F4.3 Cursor Backend

**Phase**: 4 — Agent Backends
**Priority**: High
**Dependencies**: F4.1

## Goal

Drive the `cursor-agent` CLI (Cursor's headless coding agent) for steps assigned to Cursor.

## Invocation

```
cursor-agent --print \
  --model <model> \
  --output-format text
```

- Run in the worktree.
- Prompt fed via stdin (or `--prompt-file` if available).
- MCP config: Cursor reads `.cursor/mcp.json` from the workspace root. The backend writes an ephemeral one for the duration of the spawn — keyed on `runId`/`taskId` so concurrent spawns don't stomp — and restores any prior file on completion. **Never edits the user's existing `.cursor/mcp.json` permanently.**

## Skills

Cursor reads `.cursor/rules/<name>.mdc`. The Phase 8 emitter ensures these exist project-wide; the backend just adds `--rules <name>` flags (or relies on auto-attached rules if globs are configured).

## Availability Probe

- Check `cursor-agent --version`.
- If the user has set `agents.cursor.bin` in config, use that binary.

## Output Parsing

`cursor-agent` emits human-readable text lines plus tool-call markers. The backend treats each line as a `stdout` event; `[tool: <name>]` markers (or whatever Cursor's stable convention is at release time) become `tool-use` events.

## Caveats Surfaced via Diagnostics

If Cursor's CLI is unstable across versions, the backend records the version observed and emits a `warn` log when the parsed format looks unexpected. We do not silently swallow garbled output.

## Acceptance Criteria

- Same conformance suite as F4.2.
- Ephemeral MCP config is removed even if the spawn is cancelled.
- A pre-existing `.cursor/mcp.json` is preserved bit-for-bit after the spawn.
