# F4.7 Backend Detection & `yaao agents`

**Phase**: 4 — Agent Backends
**Priority**: High
**Dependencies**: F4.1 - F4.6

## Goal

A single capabilities probe used by `yaao validate`, `yaao doctor`, and the planner skill. Plus a user-facing `yaao agents` command that prints the report.

## API

```typescript
// src/agents/detect.ts
export interface AgentAvailability {
  byName: Map<AgentName, AvailabilityReport>;
}

export async function detectAgents(config: YaaoConfig): Promise<AgentAvailability>;
```

The probe is cached for the duration of a CLI invocation (probes are not free — `gh auth status`, `claude --version`, etc. each take real time). The cache is invalidated on `--no-cache`.

## `yaao agents` Output

```
$ yaao agents
agent          status     version       notes
claude-code    ✔ ready    1.7.4         model default: opus
cursor         ✔ ready    0.45.1        skills: yaao-implementer, yaao-planner
copilot        ⚠ ready    gh 2.62 / copilot 1.20.0  not authenticated → run `gh auth login`
codex          ✘ missing  -             binary 'codex' not on PATH
api            ✔ ready                  providers: anthropic (key present), openai (no key)
```

`--json` switches to machine-readable output for CI.

## `--strict` Behavior

`yaao agents --strict` exits non-zero if any agent enabled in `yaao.config.json` is unavailable. Suitable for `prerun` checks in CI.

## Integration Points

- `yaao validate` calls `detectAgents` and uses it to distinguish disabled (config) vs not-installed (env).
- `yaao run` calls it once at the top of a run; if a needed agent is unavailable, fails fast.
- `yaao doctor` includes the report in its output.

## Acceptance Criteria

- Probe is parallelized (all backends checked concurrently).
- A backend that throws during its probe doesn't break others — its report is `{ available: false, reason: <error message> }`.
- The cache reduces a second `yaao agents` call (within the same process) to <1 ms.
