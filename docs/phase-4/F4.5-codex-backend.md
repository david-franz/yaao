# F4.5 Codex Backend

**Phase**: 4 — Agent Backends
**Priority**: High
**Dependencies**: F4.1

## Goal

Drive the `codex` CLI (OpenAI's open-source coding agent) for steps assigned to Codex.

## Invocation

```
codex exec \
  --cd <worktree> \
  --model <model> \
  --config <ephemeral-toml-overlay> \
  --json
```

- Prompt via stdin.
- `--json` (or whatever the stable structured output flag is) gives event-stream output; the backend maps it to `AgentEvent`s.
- The TOML overlay applies temporary settings (model, MCP servers) without touching `~/.codex/config.toml`. Implemented by writing a tmp file and pointing `--config` at it.

## MCP

Codex supports MCP servers in `~/.codex/config.toml` under `[mcp_servers.<name>]`. The ephemeral overlay declares the ctx-sys server for the duration of the spawn.

## Skills

Codex reads `AGENTS.md` files. The Phase 8 emitter writes a managed block into the project's `AGENTS.md` (and into per-subdirectory `AGENTS.md` if requested). The backend additionally inlines the active skill body into the prompt for explicit selection (Codex doesn't have a `--skill` flag).

## Availability Probe

- `codex --version` runs.
- Authentication: if Codex requires an API key (varies by build), the backend checks for `OPENAI_API_KEY` or whatever the configured auth path is, and surfaces a clear reason if absent.

## Output Mapping

- Streamed tool calls → `tool-use`.
- Reasoning/thinking lines → `thinking`.
- Final assistant text → `stdout`.

## Acceptance Criteria

- Conformance suite passes.
- TOML overlay never persists past the spawn; user config is untouched.
- Inlined skill body is visible to the model (verified by recording transcript).
