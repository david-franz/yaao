# F4.4 GitHub Copilot Backend

**Phase**: 4 — Agent Backends
**Priority**: High
**Dependencies**: F4.1

## Goal

Drive GitHub Copilot's coding-agent CLI for steps assigned to Copilot. This is a first-class v1 backend.

## Invocation

GitHub ships `gh copilot` as a `gh` extension and is rolling out a coding-agent mode. The exact subcommand and flags evolve; the backend pins to a tested version range and surfaces a clear error if the installed version doesn't expose the needed surface.

```
gh copilot agent run \
  --workspace <cwd> \
  --prompt-file <tmp> \
  --model <model> \
  --instructions-file <prompt with system-directive>
```

Fallback path (if the above flags shift): the backend reads `agents.copilot.invocation` from `yaao.config.json`, an array of args supporting templated placeholders (`{cwd}`, `{prompt-file}`, `{model}`, `{mcp-config}`). This lets users pin to whatever the current Copilot CLI is doing without a yaao release.

## Authentication

Copilot uses the user's existing `gh auth` session. The backend does not handle login. If `gh auth status` reports unauthenticated, `isAvailable()` returns false with `reason: 'gh not authenticated; run gh auth login'`.

## Skills / Instructions

Copilot reads two files:
- `.github/copilot-instructions.md` — repo-wide instructions, appended to by the Phase 8 emitter.
- `.github/prompts/<name>.prompt.md` — named prompt files (the Phase 8 emitter produces one per skill).

The backend references the right prompt file via `--prompt-file` for the active skill.

## MCP

Copilot's coding agent can attach MCP servers via a config file (or via `gh copilot mcp` config commands). The backend writes a workspace-local config and points Copilot at it; like Cursor, it preserves any prior config.

## Availability Probe

- `gh --version` exists and is recent.
- `gh extension list` includes a Copilot extension (or `gh copilot --version` succeeds).
- `gh auth status` is authenticated.
- Copilot subscription active (best effort: a benign `gh copilot agent --help` exits 0).

If any check fails, return false with the most actionable reason.

## Acceptance Criteria

- Conformance suite passes.
- Unauthenticated user gets the precise reason; doesn't try to spawn.
- The user can override the invocation via `agents.copilot.invocation` in config and the backend runs that exact command.
