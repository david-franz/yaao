# F4.1 AgentBackend Interface

**Phase**: 4 — Agent Backends
**Priority**: Critical
**Dependencies**: F1.5

## Goal

A single interface every agent — Claude Code, Cursor, Copilot, Codex, raw API — implements. Captures invocation, streaming output, cancellation, and an availability probe.

## Interface

```typescript
// src/agents/backend.ts
export type AgentName = 'claude-code' | 'cursor' | 'copilot' | 'codex' | 'api';

export interface SpawnOptions {
  cwd: string;                       // worktree path
  prompt: string;                    // full prompt body
  systemPrompt?: string;             // injected before prompt (used by F7 for ctx-sys directives)
  model?: string;
  skills?: string[];                 // resolved skill names; backend translates to its own format
  mcpServers?: McpServerConfig[];    // F7.2 injects ctx-sys here
  env?: Record<string, string>;
  timeout?: number;                  // ms; cancel after
  signal?: AbortSignal;
}

export interface AgentEvent {
  type: 'stdout' | 'stderr' | 'tool-use' | 'thinking';
  data: string;
  timestamp: string;
}

export interface AgentProcess {
  pid?: number;
  events: AsyncIterable<AgentEvent>; // streaming output
  completed: Promise<AgentResult>;
  cancel(reason?: string): Promise<void>;
}

export interface AgentResult {
  exitCode: number;
  stdout: string;                    // concatenated transcript (for the journal)
  stderr: string;
  toolUseCount: number;
  mcpToolCalls: McpToolCall[];       // captured via MCP server logs (F7.3 needs this)
  durationMs: number;
}

export interface AgentBackend {
  readonly name: AgentName;
  isAvailable(): Promise<AvailabilityReport>;
  spawn(opts: SpawnOptions): Promise<AgentProcess>;
}

export interface AvailabilityReport {
  available: boolean;
  version?: string;
  reason?: string;                   // populated when !available
}
```

## Why an `AsyncIterable<AgentEvent>` instead of streams?

- Simple to consume (`for await`).
- Lets each backend normalize its own format (Claude Code's stream-json, Codex's plain text, API SDK token stream) into one shape.
- The TUI (F11.4) and journal (F3.4) both subscribe via the same iterator pattern.

## Cancellation

- `cancel()` sends `SIGTERM` to the agent process; after 5 s, `SIGKILL`.
- The events iterator completes; `completed` rejects with `AgentCancelledError`.
- Cancellation reasons (timeout, user, dep-failed) are surfaced for journal entries.

## Skill Translation

Each backend translates the abstract skill list into its native format:
- `claude-code`: passes `--skill <name>` for each (or writes a transient `.claude/skills/<name>/` if `--skill` isn't supported).
- `cursor`: ensures `.cursor/rules/<name>.mdc` exists.
- `copilot`: ensures `.github/prompts/<name>.prompt.md` exists and references it via `--prompt`.
- `codex`: appends skill bodies into the request prompt as additional system messages.
- `api`: inlines skill bodies as system messages.

The skill emitters (Phase 8) are responsible for ensuring those files exist; backends don't write them.

## Errors

- `AgentUnavailableError` (`YAAO_AGENT_UNAVAILABLE`) — `spawn` called when `isAvailable()` is false.
- `AgentTimeoutError` (`YAAO_AGENT_TIMEOUT`) — exceeded `timeout` ms.
- `AgentCancelledError` (`YAAO_AGENT_CANCELLED`).
- `AgentNonZeroExitError` (`YAAO_AGENT_NONZERO`) — exit code != 0 with no captured cause.

## Acceptance Criteria

- A `FakeBackend` reference implementation exists for tests, scripts deterministic events.
- All errors thrown from `spawn` derive from `YaaoError`.
- Cancellation is exercised in the conformance suite below.

## Conformance Suite

Each concrete backend must pass `tests/phase-4/conformance/<name>.test.ts` covering:

- `isAvailable()` returns false in an empty environment.
- `spawn` rejects with `AgentUnavailableError` when unavailable.
- A trivial prompt yields at least one `stdout` event and a successful `AgentResult`.
- Timeout cancels and produces `AgentTimeoutError`.
- Manual `cancel()` produces `AgentCancelledError`.
