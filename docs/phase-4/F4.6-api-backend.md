# F4.6 API Backend

**Phase**: 4 — Agent Backends
**Priority**: Critical
**Dependencies**: F4.1, F1.3

## Goal

Run a step against a raw model API (Anthropic, OpenAI, OpenRouter) without going through any agent CLI. Lets users opt into "just call the model" for steps that don't need a full coding-agent harness.

## Provider Layer

```typescript
// src/agents/api/provider.ts
export interface ApiProvider {
  name: 'anthropic' | 'openai' | 'openrouter';
  isAvailable(config: ApiProviderConfig): AvailabilityReport;
  run(req: ApiRunRequest, signal: AbortSignal): AsyncIterable<AgentEvent>;
}
```

Each provider's `run` opens a streaming chat-completions/messages request, runs a tool-use loop until the model emits a final response, and yields events.

## Tools Exposed to the Model

The API backend wires up a small, deterministic toolbelt the model can use to actually edit code:

| Tool | Purpose |
|------|---------|
| `read_file(path)` | Read a file in the worktree. |
| `write_file(path, contents)` | Create/overwrite a file. |
| `apply_patch(diff)` | Unified-diff patch (preferred for edits). |
| `run_shell(cmd, timeout?)` | Run a command in the worktree (sandboxed PATH). |
| `list_files(glob?)` | List files matching a glob. |

All tool calls are scoped to the worktree path; absolute paths and `..` traversal are rejected.

When `ctx-sys` is enabled (F7), the MCP `context_query` tool is exposed alongside these as a native tool definition.

## Prompt Caching

For Anthropic, the backend uses prompt caching with the system prompt + skill bodies marked as cacheable. For OpenAI, it uses the cache-friendly request shape where available. This matters because per-step costs add up across a parallel run.

## Model Selection

`task.api.model` is required when `agent: api`. Provider is required (`task.api.provider`).

The backend explicitly defaults to **Claude 4.7 Opus** (`claude-opus-4-7`) when `provider: anthropic` and no model is given, since Claude is yaao's reference target. Other providers require an explicit model.

## Streaming Output

- Token deltas → `stdout` events (one event per chunk, debounced to ~50ms granularity to avoid TUI thrash).
- Tool calls → `tool-use` events with the tool name and JSON input.
- Tool results are *not* re-emitted as events (they're internal to the loop), but each tool invocation is logged for transparency.

## Errors

- `ApiKeyMissingError` — provider has no resolvable key.
- `ApiRateLimitedError` — provider returned 429; the backend respects `Retry-After` once and gives up after.
- `ApiToolLoopBudgetError` — exceeded `task.tool-budget` (default 50 tool calls per step).

## Acceptance Criteria

- Conformance suite passes (using a recorded-transcript transport in CI).
- Unified diffs apply correctly; malformed diffs raise a tool error visible to the model so it can correct.
- Tool calls outside the worktree are blocked with a clear error returned to the model.
- `ctx-sys` `context_query` is callable when configured.
