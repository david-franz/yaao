# F7.1 ctx-sys Detection & Auto-spawn

**Phase**: 7 — ctx-sys Integration
**Priority**: High
**Dependencies**: F1.3

## Goal

When `ctx-sys.enabled: true`, ensure a ctx-sys MCP server is reachable for the duration of a run, without requiring the user to manage a long-running daemon.

**ctx-sys is fully optional.** The default config ships with `ctx-sys.enabled: false`. yaao never installs ctx-sys, never auto-detects-and-enables, and runs perfectly without it. When the user does opt in, the integration is proactive (auto-spawn defaults to true *within the enabled state*), not deferred or lazy.

## Detection

```typescript
// src/ctx-sys/detect.ts
export interface CtxSysStatus {
  installed: boolean;          // `ctx-sys` binary on PATH
  initialized: boolean;        // .ctx-sys/ directory present in project
  running: boolean;            // a ctx-sys server already serving this project
  socketPath?: string;         // resolved socket if running
  version?: string;
}
export async function detectCtxSys(cwd: string, config: YaaoConfig): Promise<CtxSysStatus>;
```

Probes:
1. `which ctx-sys` (or `config['ctx-sys'].bin` if overridden).
2. Existence of `.ctx-sys/` in `cwd` (or any ancestor up to the git root).
3. Existence of a project socket at `.ctx-sys/yaao-mcp.sock`. If present, `nc -U` (or a TCP-style probe) for a quick handshake.
4. `ctx-sys --version`.

## Auto-spawn

If `auto-spawn: true` and ctx-sys is installed but not running:

### Index-missing behavior

ctx-sys serves whatever index the project has — including an empty one. A `serve` against an unindexed project hands back zero results, and agents then make worse decisions silently. Before spawning, yaao probes the project's index state (presence of `.ctx-sys/db.sqlite` plus a non-zero entity count via `ctx-sys status --json`):

- **Index missing entirely** → yaao aborts the run with a clear message: "ctx-sys is enabled but the project is not indexed. Run `ctx-sys init && ctx-sys index`, then retry, or set `ctx-sys.enabled: false` to disable." `--force` bypasses this and proceeds with an empty index, journaling the override.
- **Index present but stale** (mtime older than the newest tracked-file mtime by some configurable threshold) → yaao logs a warning and continues. Auto-reindex is **not** in scope for v1; users opt in via `ctx-sys watch` separately.
- **Index present and reasonably fresh** → spawn proceeds normally.

This check runs once per `yaao run` invocation, before any task is spawned, so the abort happens before worktrees are created.

```typescript
// src/ctx-sys/spawn.ts
export interface CtxSysHandle {
  socketPath: string;
  pid: number;
  shutdown(): Promise<void>;
  events: AsyncIterable<{ type: 'log'; line: string }>;
}

export async function spawnCtxSys(cwd: string, config: YaaoConfig): Promise<CtxSysHandle>;
```

Steps:
1. Pick a project-scoped socket path: `<cwd>/.yaao/ctx-sys.sock`.
2. Spawn `ctx-sys serve --socket <path>` with `cwd: <cwd>`, `stdio: pipe`.
3. Wait for a "ready" log line or a socket-handshake (whichever comes first), with a 10 s timeout.
4. Return the handle. The runner takes ownership and calls `shutdown()` on `run:end`.

## Lifecycle

- yaao spawns one ctx-sys per run, even if multiple tasks need it.
- The handle is shared across all task spawns in F7.2.
- If yaao is `kill -9`'d, the orphaned ctx-sys process exits when its socket closes (handled by ctx-sys itself).

## Configuration Surface

Default in shipped config:

```json
"ctx-sys": { "enabled": false }
```

Opted-in:

```json
"ctx-sys": {
  "enabled": true,
  "auto-spawn": true,
  "bin": "ctx-sys",
  "socket": ".yaao/ctx-sys.sock",
  "spawn-timeout-ms": 10000
}
```

## Acceptance Criteria

- With `auto-spawn: true` and ctx-sys installed, `yaao run` produces a working MCP server reachable from each task spawn.
- With `auto-spawn: false` and no running server, the run continues but agents lack ctx-sys context (warning logged).
- Spawn timeout produces a clear, actionable error.
- Server is cleanly shut down when the run ends (no orphan processes).
