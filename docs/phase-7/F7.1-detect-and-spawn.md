# F7.1 ctx-sys Detection & Auto-spawn

**Phase**: 7 — ctx-sys Integration
**Priority**: High
**Dependencies**: F1.3

## Goal

When `ctx-sys.enabled: true`, ensure a ctx-sys MCP server is reachable for the duration of a run, without requiring the user to manage a long-running daemon.

**ctx-sys is fully optional.** The default config ships with `ctx-sys.enabled: false`. yaao never installs ctx-sys, never auto-detects-and-enables, and runs perfectly without it. When the user does opt in, the integration is proactive (auto-spawn defaults to true *within the enabled state*), not deferred or lazy.

## Detection

```typescript
// src/ctx-sys/detect.ts
export interface CtxSysStatus {
  installed: boolean;          // `ctx-sys` binary on PATH
  initialized: boolean;        // .ctx-sys/ directory present in project
  running: boolean;            // a ctx-sys server already serving this project
  socketPath?: string;         // resolved socket if running
  version?: string;
  indexed?: boolean;           // `.ctx-sys/db.sqlite` exists and is non-empty
  reason?: string;             // populated when the status reports a problem
}

export interface DetectOptions {
  cwd: string;
  config: YaaoConfig;
  bin?: string;                // test injection: override the `ctx-sys` binary name
}

export async function detectCtxSys(opts: DetectOptions): Promise<CtxSysStatus>;
```

Probes (pure inspection — never spawns; the caller decides what to do with the report):

1. `ctx-sys --version` — checks PATH presence *and* captures the version in one call. `opts.bin` overrides the binary name for tests.
2. Walk up from `cwd` looking for `.ctx-sys/`, stopping at the git root.
3. Existence of a project socket at `.ctx-sys/yaao-mcp.sock` (file existence only — no handshake; staleness surfaces lazily on the agent's first `context_query` call).
4. If initialized, `.ctx-sys/db.sqlite` presence + non-zero size, used as a proxy for index health. Populates `indexed?` and a human-readable `reason?` when empty.

## Auto-spawn

If `auto-spawn: true` and ctx-sys is installed but not running:

### Index-missing behavior

ctx-sys serves whatever index the project has — including an empty one. A `serve` against an unindexed project hands back zero results, and agents then make worse decisions silently. Before spawning, yaao probes the project's index state (presence of `.ctx-sys/db.sqlite` plus a non-zero entity count via `ctx-sys status --json`):

- **Index missing entirely** → yaao aborts the run with a clear message: "ctx-sys is enabled but the project is not indexed. Run `ctx-sys init && ctx-sys index`, then retry, or set `ctx-sys.enabled: false` to disable." `--force` bypasses this and proceeds with an empty index, journaling the override.
- **Index present but stale** (mtime older than the newest tracked-file mtime by some configurable threshold) → yaao logs a warning and continues. Auto-reindex is **not** in scope for v1; users opt in via `ctx-sys watch` separately.
- **Index present and reasonably fresh** → spawn proceeds normally.

This check runs once per `yaao run` invocation, before any task is spawned, so the abort happens before worktrees are created.

```typescript
// src/ctx-sys/spawn.ts
export interface SpawnCtxSysOptions {
  cwd: string;
  bin?: string;                // defaults to 'ctx-sys'
  socketPath?: string;         // defaults to <cwd>/.ctx-sys/yaao-mcp.sock
  spawnTimeoutMs?: number;     // defaults to 10_000
}

export interface CtxSysHandle {
  socketPath: string;
  pid: number;                 // 0 when reusing an already-running ctx-sys
  ownsProcess: boolean;        // false when an already-running instance was reused
  spawned: boolean;            // true when this call started ctx-sys; false on reuse
  shutdown(): Promise<void>;   // for tests; production runners do NOT call this (see Lifecycle)
}

export async function spawnCtxSys(opts: SpawnCtxSysOptions): Promise<CtxSysHandle>;
```

Steps:

1. Pick a project-scoped socket path: `<cwd>/.ctx-sys/yaao-mcp.sock`. The socket lives under `.ctx-sys/` (not `.yaao/`) so `yaao clean` / `yaao_prune` — which scrub `.yaao/` — don't tear down the running ctx-sys, and so detect + spawn agree on where to look.
2. Spawn `ctx-sys serve --socket <path>` `detached: true` with `cwd: <cwd>`, `stdio: ['ignore', 'pipe', 'pipe']`.
3. Wait for a "ready" / "listening" log line on the child's stdout, with a 10 s timeout.
4. `unref()` the child and destroy our ends of stdout/stderr so node's event loop is no longer pinned. Return the handle.

## Lifecycle

- yaao spawns one ctx-sys per run, even if multiple tasks need it.
- The handle is shared across all task spawns in F7.2.
- **yaao does NOT call `shutdown()` at run-end** — the contract is "spawn if not running, leave it running afterwards" so the indexer stays warm across runs. The `shutdown()` method on the handle is for tests (cleaning up the processes they started); production runners simply let the detached child outlive them. Re-running `yaao run` reuses the existing socket without respawning.
- If yaao is `kill -9`'d, the detached ctx-sys keeps serving on its socket (it's in its own process group). The next `yaao run` reuses it.
- A crashed ctx-sys leaves its socket file behind. yaao does not probe liveness pre-spawn; the staleness surfaces as a connection refused on the agent's first `context_query` call. Manual recovery: `rm .ctx-sys/yaao-mcp.sock` and rerun. `yaao doctor` (F14.1) is the right home for a liveness probe.

## Configuration Surface

Default in shipped config:

```json
"ctx-sys": { "enabled": false }
```

Opted-in:

```json
"ctx-sys": {
  "enabled": true,
  "auto-spawn": true,
  "require-query": false
}
```

These three fields are the entire user-facing config surface (see [src/config/schema.ts](../../src/config/schema.ts)). `bin`, `socketPath`, and `spawnTimeoutMs` are programmatic options on `SpawnCtxSysOptions` for tests; they are not exposed in `yaao.config.json` and the socket path is fixed at `.ctx-sys/yaao-mcp.sock`.

## Acceptance Criteria

- With `auto-spawn: true` and ctx-sys installed, `yaao run` produces a working MCP server reachable from each task spawn.
- With `auto-spawn: false` and no running server, the run continues but agents lack ctx-sys context (warning logged).
- Spawn timeout produces a clear, actionable error.
- ctx-sys is **intentionally left running** after the run completes — the warm-index design means the next run reuses the socket without respawning. There is no "no orphan processes" guarantee here, by design. Tests clean up by explicitly calling `handle.shutdown()`.
