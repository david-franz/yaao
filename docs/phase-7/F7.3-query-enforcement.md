# F7.3 ctx-sys Advisory Directive

**Phase**: 7 — ctx-sys Integration (optional)
**Priority**: Medium
**Dependencies**: F7.1, F7.2

## Goal

When ctx-sys is enabled, prepend a strong system-prompt directive to every step encouraging the agent to call `context_query` before writing code. **Advisory only** — yaao does not fail tasks for skipping the call. The agent decides.

This is a deliberate downgrade from a hard "require-query" enforcement gate. Hard enforcement produced low-quality, performative tool calls (an agent satisfying the gate by calling `context_query("auth")` with no real intent). The advisory keeps the upside (agents have ctx-sys top-of-mind) without the downside (gaming the gate).

## System-prompt Directive

```
This project uses ctx-sys for codebase context. BEFORE writing or modifying code,
you SHOULD call the `context_query` MCP tool with a query relevant to the task. Examples:
  - "How is authentication wired up?"
  - "Where is the database schema defined?"
You may call it multiple times. The tool returns curated context from this codebase.

If the task is trivial (a typo fix, a one-line bump) you may skip the query.
```

The directive is suppressed if the user supplies their own `task.systemPrompt`. The directive is *not* added when ctx-sys is disabled.

## Per-task Override

A task can suppress the directive entirely:

```yaml
- id: trivial-readme-edit
  context:
    ctx-sys:
      directive: false
```

## Observability (no enforcement)

yaao still records `mcpToolCalls` per task (from F4.1's `AgentResult`) and surfaces a per-task counter in `yaao status`:

```
id            status     ctx-queries
api           ✔ done     4
ui            ✔ done     0          (warning: produced 11 file diff)
```

The counter is informational. A task with zero queries and a non-empty diff gets a TUI/log warning but does **not** fail. Users who want to enforce a policy can write a custom validation command (`task.validation.command`) that inspects the run journal and fails the task — yaao itself does not.

## Acceptance Criteria

- The directive is injected verbatim into every step's system prompt when ctx-sys is enabled and not overridden.
- `directive: false` per-task suppresses the directive cleanly.
- `mcpToolCalls` counts are accurate and visible in `yaao status`.
- A task with zero queries and a non-empty diff produces a warning, not a failure.
- The directive is absent entirely when ctx-sys is disabled.
