# F14.5 README + IMPLEMENTATION.md accuracy pass

**Phase**: 14 — Release Polish
**Priority**: Medium
**Dependencies**: none

## Goal

The README and IMPLEMENTATION.md describe yaao exactly as it ships, not as it was scoped. Several drifts have accumulated; close them before v1.

## Known drifts to close

- **API backend status.** README says "shipped (loop + sandbox; provider SDKs are stubs)" but the Anthropic provider is now real (native `fetch`, tool-use loop, prompt caching). Update the language; remove the "stubs" hedge for Anthropic; keep it for OpenAI / OpenRouter if those are still placeholder.
- **`yaao agents` command.** Today's README lists it; with F14.1 it's subsumed by `yaao doctor`. Either remove or mark as a thin alias.
- **`format: both` plan output.** Niche; either keep documented or remove from the `yaao plan` flag table — don't leave it ambiguously supported.
- **`--scope project` multi-phase plans.** Documented as shipped; in practice rarely exercised. Mark as "experimental — may change" in the README until F14.6 has actually run a project-scope plan end-to-end.
- **`yaao web` first-time auth flow.** README mentions `--token` but the actual behaviour (token-via-query-string on first load, persisted to localStorage) isn't documented.
- **MCP tool surface.** README claims `yaao_inspect` / `yaao_prune` / `yaao_resume` ship; confirm each appears in `src/mcp/server.ts` and matches the documented input shape.
- **Phase numbers everywhere.** This phase swap (old 14↔15, new 16) means README's "Planned phases" and any phase-N references need to track. F14.5 sweeps for stale ones.

## Process

1. Read the README top-to-bottom. For every claim about behaviour, grep the source to confirm it matches.
2. Read IMPLEMENTATION.md's phase tables. For every "shipped" entry, sanity-check the docs and source exist.
3. Sweep for stale phase-N / F-N.M references after the phase renumbering.
4. Land everything as one commit; the diff is the auditable trace of what was wrong.

## Acceptance criteria

- Every claim in the README about a feature being shipped corresponds to code that's actually in `src/`.
- Every link in IMPLEMENTATION.md resolves.
- No section of the README contradicts another.
- The "Planned phases" block matches what's actually planned for v1.

## Tests

- `tests/phase-14/docs/links.test.ts` — walks every `[label](path)` link in README and `docs/**/*.md`; asserts the target exists. Cheap, catches every dangling reference the truth-up introduces or fixes.

## Out of scope

- A docs site (Phase 17). The truth-up is to the README + the in-repo docs; the long-form site is a separate phase.
- Restructuring the README for marketing. This is a correctness pass, not a rewrite.
