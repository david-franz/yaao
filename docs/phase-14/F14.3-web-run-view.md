# F14.3 Web Live Run View

**Phase**: 14 — Web Viewer
**Priority**: High
**Dependencies**: F14.1, F14.2

## Goal

The browser equivalent of `yaao run`'s live monitor. The same DAG canvas as F14.2, plus live status overlays, a task-table tab, and an **activity stream** that surfaces what each agent is actually doing — not just stdout/stderr.

Runs are started elsewhere (CLI `yaao run` or MCP `yaao_run`); this view watches them. That keeps the spawning lifecycle in one place (the runner the CLI / MCP server already uses) and lets the web viewer focus on rendering live state.

## Pages

- `/runs/:runId` — live run view.
- `/runs/:runId/tasks/:id` — focused task with full activity scrollback.
- `/runs/latest` — redirect to the most recent run (the default landing page after `yaao web`).

## Live Updates

- Subscribes to `GET /api/runs/:runId/events` (SSE).
- Reconnect-on-drop with `Last-Event-ID` for replay since the last received event. Resumed runs continue seamlessly — same runId, same event stream.
- DAG nodes change color/badge on `task:*` events.
- Task table tab updates in place.
- For finished runs the SSE stream replays from journal and then closes; the client renders the final state without further updates.

## The activity stream (the part that makes this useful)

The bus already emits `task:agent-event` with `ev.type` ∈ `{ stdout, stderr, thinking, tool-use }` ([src/agents/backend.ts:51](../../src/agents/backend.ts#L51)), plus structured events like `task:retry-attempt`, `task:diff`, `task:committed`, `task:merged`, `task:failed`. F14.1's SSE forwards every one of these. The web run view renders them as a unified stream, not a raw stdout tail, because watching `tail -f output.log` is what the TUI gives you — the web viewer should be doing more.

Row shapes:

| Event | Default row | Expansion |
| --- | --- | --- |
| `task:active` | "▶ kheap-core started (claude-code · opus, branch `kheap/kheap-core`)" | — |
| `task:agent-event` `type:'tool-use'` | "→ tool: `Bash` (cd src && make)" | full args block on click |
| `task:agent-event` `type:'thinking'` | "· thinking (412 chars)" — collapsed by default | full thinking body on click |
| `task:agent-event` `type:'stdout'` | a single line, ANSI-rendered | join consecutive stdout chunks into one expandable block |
| `task:agent-event` `type:'stderr'` | red-tinted line | same |
| `task:retry-attempt` | "↻ attempt 2 of 2 — validation failed: `make && nm ...` exited 1" | stdout/stderr tails on click |
| `task:diff` | "+128/-7 across 4 file(s)" | per-file list on click |
| `task:committed` | "✓ committed `a3f7e0c`" | commit subject on click |
| `task:merged` | "↪ merged into main as `b1c2d3e`" | — |
| `task:merge-failed` | "⚠ merge into main failed — conflicts: src/api/route.ts" | full conflict list on click |
| `task:completed` | "✓ completed in 47s — validation: exit 0" | the recorded `validation: { command, exitCode, decisionReason }` from the journal |
| `task:failed` | "✗ failed — YAAO_AGENT_NONZERO: ..." | error tails + the validation block |

Stream UX:

- **Per-task filter**: clicking a DAG node filters the stream to that task's events. Esc clears.
- **Follow tail toggle**: on by default; turns off on user scroll-up, snaps back on scroll-to-bottom.
- **Search**: `/` opens a substring filter over the rendered rows.
- **Open in new tab**: link to `/runs/:runId/tasks/:id` for full scrollback (the page's filter is pre-set to that task).
- **ANSI** support for stdout/stderr (`xterm-256color`).
- **Thinking blocks are dimmed and collapsed by default**: agents emit a lot of these and they're noise unless the user explicitly wants to follow the reasoning. Click expands inline.

## Task detail pane

Right side, mirrors F14.2's plan detail pane but adds run state:

- Agent + model used; cached worktree marker + pointer to `cachedFromRunId` (links to that run).
- Branch and committed SHA; merge target + merge commit when merged.
- **Validation outcome surfacing** (the recorded `validation: { command, exitCode, decisionReason, durationMs, mustPass }`): a "✓ validation passed (exit 0)" or "✗ validation failed (exit 1)" pill with the command body and stdout/stderr tails on click. This is the part that made the false-positive-merge bug catchable; the UI should make it a first-class signal, not a buried log line.
- Files changed list.
- If task failed: the captured prior-failure context that the next attempt would receive.

## Controls

- **Cancel run** button (POSTs to `/api/runs/:runId/cancel`). Disabled when the run isn't in-flight.
- **Resume run** button (POSTs to `/api/runs/:runId/resume`). Shows on any non-success status. Two checkboxes: "retry failed tasks" (default on) and "leave skipped tasks skipped" (default off) — same options as the `yaao_resume` MCP tool's `retryFailed` and `reskip` flags. The run continues under the same runId, the page stays put, SSE picks up the new events.
- **Detach**: close the tab; the run keeps going, the server stays up.

Run *creation* is deliberately not here. Start a run from your terminal or your MCP-aware editor; come to the web view to watch it.

## URL State

- The selected task and tab (graph / table / activity-only) is encoded in the URL hash so bookmarks and refresh work.
- `/runs/latest` is the default landing — redirects to the newest `RunSummary.startedAt`.

## Acceptance Criteria

- Live view updates within ~1 s of the SSE event firing.
- Reconnection after a 5-second network drop replays missed events via `Last-Event-ID` without duplicates.
- Thinking events appear as collapsed rows by default; tool-use rows are always expanded to one line.
- The validation outcome (exitCode + decisionReason) is rendered in the task detail pane for every task that ran validation.
- Cancel button works and is idempotent. Resume button works against a `failed` run and produces a `success` state in-place when the resumed attempt completes.
- Browser refresh restores the same visual state (selected task, active tab, scroll position via the URL hash).
- Run creation is **not** offered in the UI — no "start run" button anywhere.
