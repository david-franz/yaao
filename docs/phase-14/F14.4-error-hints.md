# F14.4 Error message + hint audit

**Phase**: 14 — Release Polish
**Priority**: Medium
**Dependencies**: F1.5

## Goal

Every `YaaoError` a new user can hit during `init` / `plan` / `convert` / `validate` / `run` / `web` / `serve` carries a `hint:` that points at the fix. Today coverage is patchy — some paths have great hints (the plan-tracking gate, the secret-leakage rejection), others throw bare error messages that require reading source to decode.

## Process

1. Enumerate every `throw new YaaoError(...)` site in `src/`. Bucket by command path.
2. For each error, ask:
   - Can a user trigger it during a normal flow (i.e. is it an invariant or a real user-facing failure)?
   - If user-facing, does it tell them what to do next?
3. Add a `hint:` where it's missing. Strip stale hints where the workaround has been built into the engine (e.g. anywhere that says "run `yaao clean`" should now point at `yaao_prune`).

## Style guide for hints

- Imperative, second person: "run `X`", not "the user should run `X`".
- Reference real commands, not phases of work. ("run `yaao init`" not "complete project initialisation").
- One sentence max. Multi-step recoveries belong in a doc page the hint links to, not in the hint itself.
- Don't echo the error message. The hint adds *new* information.

## Specific call-outs

- `YAAO_AGENT_UNAVAILABLE` — currently says "the binary isn't on PATH"; should suggest `yaao doctor` (after F14.1 ships).
- `YAAO_PLAN_UNTRACKED` — already has a good hint; check the wording matches the new `--allow-untracked-plan` flag name.
- `YAAO_PLAN_API_NO_KEY` — should mention both `.yaao/secrets.local.json` *and* env vars; today it only mentions secrets.local.
- `YAAO_PLAN_NARROW_DAG` (F45bebdd, just-shipped) — already a warning not an error, but the wording is long; tighten.
- Web-server auth errors — should point at `--token` for non-loopback binds.

## Acceptance criteria

- 100% of user-facing `YaaoError` instances carry a `hint:`.
- Every hint passes the four style-guide rules above (manual review).
- No hint references a CLI command or flag that doesn't exist.

## Tests

- `tests/phase-14/error-hints/coverage.test.ts` — walks the test corpus for every YaaoError code the codebase declares; asserts each produces a non-empty `hint` field in at least one test fixture. Coverage check, not behaviour check.
- Existing per-feature tests stay unchanged.

## Out of scope

- A typed error-code enum to replace string codes. Tempting but not the v1 hill to die on; the audit is the deliverable.
- Localisation of error messages.
