# F14.4 Web Workspace View

**Phase**: 14 — Web Viewer
**Priority**: High
**Dependencies**: F14.1, F12-era yaao_inspect + yaao_prune

## Goal

A single page that shows the workspace as yaao sees it — every plan, every run, every alive worktree and branch — and offers structured cleanup affordances over the same `yaao_prune` contract the MCP tool exposes. This is what `yaao_inspect` + `yaao_prune` look like as a browser page.

Without this, the web viewer is just "watch the current run" and "browse history." Adding it makes the web the natural place to live for everything that isn't actually starting runs.

## Pages

- `/workspace` — the snapshot. Default landing for new users with no runs.

## Layout

Three sections, vertically stacked:

### Workspace summary card

Reads from `GET /api/inspect`. Shows `workspace.cwd`, `baseBranch`, `defaultAgent`, `worktreeRoot`, and the `configPath` with a link to the config editor (F14.6). The `inRepo: false` case is loud — a red banner explaining yaao runs outside a git repo skip the plan-tracking gate and the worktree-stamp lineage.

### Plans table

One row per plan slug (union of `.yaao/plans/<slug>.md` and `.yaao/exec/<slug>.yaml`). Columns:

| Column | Source |
| --- | --- |
| Slug | derived |
| Plan file | `plans[].planPath` — links to F14.5's editor |
| Exec file | `plans[].execPath` — links to F14.2's DAG view |
| Tracked? | `plans[].tracked` / `plans[].dirty` — green / yellow / red dot |
| Plan commit | `plans[].planCommit` — short SHA, links to git log if a remote is configured |
| Last run | `plans[].lastRunId` + `lastRunStatus` + `lastRunEndedAt` — clickable to the run page |

The "tracked" column is the user-facing surface for the `YAAO_PLAN_UNTRACKED` gate. Yellow ("dirty") means the plan file has uncommitted changes; clicking opens the editor with the diff visible.

### Runs table

One row per run, newest first. Columns:

| Column | Source |
| --- | --- |
| Run ID | `runs[].runId` — links to `/runs/:runId` (F14.3) |
| Plan | `runs[].planSlug` |
| Status | `runs[].status` pill |
| Tasks | `runs[].tasksCompleted` / `tasksFailed` / `tasksSkipped` / `tasksTotal` |
| Branches alive | `runs[].branchesAlive.length` with the list on hover |
| Started | `runs[].startedAt` (relative time) |
| Actions | per-row prune menu (see below) |

Empty branches column = the run has been pruned already. Failed/cancelled runs get a "Resume" action that POSTs to `/api/runs/:runId/resume` (same plumbing as F14.3's resume button) — convenient for failed runs you don't want to navigate into.

## Live updates

Subscribes to `GET /api/inspect/watch` (SSE, F14.1). Each event triggers a re-fetch of `/api/inspect`. Debounced 250 ms so an FS-write burst (atomic rename, multi-file edit) doesn't thrash the page. The plans + runs tables update in place; pan position and selection are preserved.

## Prune affordances

Three entry points, all hitting `POST /api/prune`:

### Per-row prune (runs table)

A "Clean up" action menu on each run row offers:
- "Remove this run's worktrees" → `{ target: 'run', runId, scope: ['worktrees'] }`
- "Remove this run's branches" → `{ target: 'run', runId, scope: ['branches'] }`
- "Remove everything (worktrees + branches + journal)" → `{ target: 'run', runId, scope: ['worktrees', 'branches', 'runs'] }`

Each opens a confirmation modal that shows the dry-run result first (yaao_prune defaults to `dryRun: true`, so the first call previews; the modal's "Apply" button re-calls with `dryRun: false`).

### Bulk prune

A "Clean up…" button above the runs table opens a modal with the broader targets:

- "All completed runs (older than N days)" — `target: 'older-than'`, configurable days.
- "All failed runs" — `target: 'all-failed'`.
- "All successful runs" — `target: 'all-completed'`.

Same dry-run-first flow.

### Skipped items handling

The prune tool's `skipped: []` array (worktrees with uncommitted changes, branches not yet merged, base-branch refused) is rendered prominently in the modal. Each row has a "Force" checkbox that, when set, adds `force: true` to the actual apply call. The base-branch refusal is always grayed out — no override.

## Restrictions

- Run *creation* is not here (mirrors F14.3 — runs start from CLI / MCP).
- No "delete plan file" affordance — that's `rm .yaao/plans/<slug>.md` territory, gitignore-able, and outside the scope of "manage yaao state." The plan editor (F14.5) is the right place for plan-file lifecycle.
- No "delete skill" affordance either — skills delete via filesystem, F12.6's watcher picks it up. F14.5's editor can add this later if needed.

## Acceptance Criteria

- `/workspace` renders the full inspect payload without any per-row API call after the initial fetch.
- A run pruned via the UI disappears from the runs table on the next inspect-watch fire (within ~250 ms).
- The dry-run preview shows the exact set of files/branches/run-dirs that would be removed; the apply call matches that set.
- A worktree with uncommitted changes is in `skipped[]` by default and can only be removed with the per-row `force` checkbox checked.
- Base-branch never appears in the `removed` list, regardless of how a malformed run journal records branches.
- The workspace page works with zero runs (renders empty state with a "start a run from the CLI: `yaao run <plan.yaml>`" instruction).
