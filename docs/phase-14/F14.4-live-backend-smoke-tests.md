# F14.4 Live Backend Smoke Tests

**Phase**: 14 — Integration Correctness
**Priority**: Medium
**Dependencies**: F4.2–F4.6 (backends)

## Goal

Prove that the CLI shapes documented for `cursor-agent`, `codex exec`,
`gh copilot agent run`, and `claude --print` still match what those
binaries actually accept and produce. Today the test suite for non-Claude
backends contains only argv-construction tests; nothing exercises the
real binary, its output parser, or its non-zero-exit handling.

This is the test backstop the rest of Phase 14 leans on. F14.1's
enable-disable plumbing, F14.2's MCP overlay swapping, and F14.3's
Anthropic caching all assume the underlying CLIs accept the flags and
emit the JSON shapes the parsers expect. Without F14.4 those assumptions
silently rot every time a vendor ships a new release.

## Current coverage gap

[tests/phase-4/](../../tests/phase-4/) by backend:

| Backend | What's tested today | What isn't |
| --- | --- | --- |
| **claude-code** | `parseClaudeStreamJsonLine` unit tests, `writeMcpConfig` write | No live spawn against `claude` |
| **cursor** | `buildCursorArgs` — argv only | No live spawn, no output parser, no failure-path test |
| **copilot** | `buildCopilotArgs` — argv only | No live spawn, no `gh auth status` integration, no output parser |
| **codex** | `parseCodexJsonLine` + `buildCodexArgs` | No live spawn |
| **api/anthropic** | FakeApiProvider script | No live HTTP call (intentional for cost; F14.4 is fine leaving this as recorded fixtures) |

The argv-only tests prove we hand the right command line. They do not
prove the CLI accepts that command line, or that our parser handles its
actual output shape.

## Design

### Skip-if-missing live tests

Each backend gets a `*-live.test.ts` file under `tests/phase-14/live/`.
Each test:

1. Checks `command -v <bin>` (or the `--version` probe the backend
   already uses).
2. If the binary is missing, calls `test.skip()` with a clear reason
   so CI doesn't flake — visible as a skipped count in the test runner
   summary, not a silent pass.
3. If the binary is present, runs a minimal task in a tmpdir worktree
   with a trivial prompt ("write a file called hello.txt containing
   the word ok"). Asserts:
   - Backend's `isAvailable()` returns `available: true`.
   - The spawn completes with exit code 0 (or a recorded acceptable
     code for backends with quirks).
   - The expected file landed on disk.
   - The output parser emitted at least one well-formed
     `AgentEvent` of each expected `type` (stdout, tool-use where
     applicable).

### CI gating

The CI workflow ([.github/workflows/ci.yml](../../.github/workflows/ci.yml))
gets a second matrix entry:

- **default job**: skips live tests, runs the rest of the suite.
  Status quo.
- **live-backends job** (optional, non-blocking on PR): installs
  `claude`, `cursor-agent`, `gh + gh-copilot`, `codex`, runs the full
  suite including `tests/phase-14/live/`. Reports separately; broken
  binaries surface as failed jobs but don't block merge.

This avoids making every PR depend on vendor CLIs being installable in
CI, while still catching breakage when someone actually runs the live
job (release branches, scheduled nightlies, manual triggers).

### Output-shape fixtures (no-binary)

For the cases where running the live binary is too expensive or
non-deterministic, add fixture-based parser regression tests:

- `tests/phase-14/parser-fixtures/cursor-output-2026-01.txt` — a real
  capture of `cursor-agent --print` output for a known prompt. Parser
  must produce the documented sequence of `AgentEvent`s.
- Same shape for codex `--json` and `gh copilot agent run`.

Update fixtures when the vendor changes their output format; the test
file's name carries the date so the version drift is visible at a
glance.

### Anthropic provider integration

`AnthropicProvider` already has FakeApiProvider coverage. F14.4 adds:

- `tests/phase-14/live/anthropic-live.test.ts` — skip-if-no-key
  pattern; one real round-trip against `claude-haiku-4-5` (cheap
  model) with a 1-tool spawn. Asserts the tool-use loop completes and
  (post-F14.3) that `cache_read_input_tokens > 0` on the second
  request. Pinned to a low-cost model; the test budget is < $0.01 per
  CI run.

## Acceptance criteria

- Five new test files under `tests/phase-14/live/`, one per backend.
  Each skips cleanly when its binary/key is unavailable.
- Five fixture-based parser regression tests under
  `tests/phase-14/parser-fixtures/`.
- `.github/workflows/ci.yml` has a `live-backends` job, scheduled to
  run on a cron (nightly) and on manual dispatch. Default PR runs
  unchanged.
- The skip output format is consistent: every skip records the
  reason (`(skipped: cursor-agent not on PATH)`) so an integrator can
  see what coverage they're losing.
- Each backend doc under `docs/phase-4/` links to the corresponding
  live test as the canonical "what version of the CLI we tested
  against" reference.

## Out of scope

- **Vendor-version matrix testing** (every supported version of every
  CLI). Pinning a single tested version per backend is enough for v1.
  Multi-version matrix is a v2 cleanup if it becomes load-bearing.
- **Performance benchmarks for backends.** F14.4 is correctness +
  shape verification, not bench.
- **Replacing the unit-level argv tests.** Those stay — they catch
  shape regressions cheaply and run on every PR. The live tests are
  *additional* coverage.
- **Forcing every contributor to install all four CLIs.** Live tests
  are skip-if-missing so the default contributor workflow is
  unchanged.
