# F14.6 End-to-end pre-release validation on real projects

**Phase**: 14 — Release Polish
**Priority**: High (gating for v1)
**Dependencies**: every other Phase 14 feature

## Goal

Before tagging v1, drive yaao through three real projects — not synthetic test fixtures — and resolve everything that breaks. The unit suite proves the engine works in isolation; this proves the engine works in the wild.

## Targets

| Project shape | Stack | Concrete plan |
| --- | --- | --- |
| TypeScript monorepo | pnpm workspaces, Next.js + Hono | Add a feature flag system across web + api |
| Python service | Flask + SQLAlchemy + pytest | Add a JWT auth middleware |
| C / embedded | the existing `c-test` OS kernel project | A 6-task feature (e.g. a network stack scaffold) |

Each project lives outside the yaao monorepo. For each, the tester:

1. `yaao init` from scratch — confirms F14.2's auto-MCP-registration works.
2. `yaao doctor` — confirms F14.1 catches the typical missing-binary / missing-key cases.
3. `yaao plan` + `yaao convert` — confirms the planner now produces parallel siblings (the F13/45bebdd nudges).
4. `yaao run` — full execution, end-to-end. At least one run with `merge: agent` conflict resolution exercised.
5. `yaao web` — open the run in the browser; click through every page.

## What to record

For every issue found, file a checklist item with:

- The exact command that triggered it.
- What the user expected vs. what they got.
- The fix (commit SHA), or "deferred to v1.1" + rationale.

The deliverable from F14.6 is not a doc — it's the set of fixes landed before v1 ships. The doc is just the trace.

## Acceptance criteria

- All three projects reach a successful `yaao run` end-to-end.
- Every issue surfaced during the runs is either fixed or explicitly deferred (with rationale committed to a `PRERELEASE-NOTES.md` that ships with v1).
- The doctor's preflight catches each of the deliberate failure modes: missing binary, expired key, no `.yaao/`, untracked plan.

## Tests

- No new unit tests from F14.6 directly. The fixes that come *out* of F14.6 each carry their own focused test, but the validation itself is human-in-the-loop.

## Out of scope

- Building a CI integration that runs against real agent APIs. Cost + flakiness — let humans drive this for v1; revisit for v2.
- Performance benchmarks. Correctness only.
