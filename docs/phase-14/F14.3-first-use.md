# F14.3 First-use experience — 60-second quickstart + `examples/`

**Phase**: 14 — Release Polish
**Priority**: High
**Dependencies**: F14.1, F14.2

## Goal

Cut the time from "I just installed yaao" to "I'm watching yaao orchestrate a parallel run" down to under a minute, with a copyable block of commands that work on a fresh machine. Today the README is comprehensive but you have to read 200 lines before you get to the first runnable command.

## Quickstart block in README

A new top-of-README section (immediately after `## Status`):

````markdown
## Quickstart

```bash
npm i -g yaao
cd my-project
yaao init                                  # writes .yaao/ + registers MCP
yaao plan "add a /healthz endpoint"        # uses your default agent
yaao convert .yaao/plans/healthz.md        # → .yaao/exec/healthz.yaml
yaao run .yaao/exec/healthz.yaml           # parallel worktrees, auto-merge
```

That's the whole flow. `yaao web` in another terminal gives you a
browser view of the run.
````

The block is copy-paste runnable end-to-end on a fresh repo. F14.1's `yaao doctor` and F14.2's auto-MCP-registration are what make this work without intermediate setup steps.

## `examples/` directory

Three real, runnable execution plans committed to the repo:

- `examples/typescript-monorepo/healthz-endpoint.yaml` — single-feature, 3-task fan-out, demonstrates `validation.cwd` for a monorepo workspace.
- `examples/python-flask/add-jwt-auth.yaml` — 4-task plan with one `merge: pr` task, demonstrates the PR-merge mode.
- `examples/c-kernel/serial-driver.yaml` — pulled in from `../c-test`, the kheap-style OS kernel feature that's been the test bed for parallelism work.

Each example directory has a `README.md` with: what the plan does, what agent backends it needs available, what the expected run looks like, and a link to the IMPLEMENTATION.md feature that motivates the shape (validation cwd inference, PR mode, parallel siblings).

## Acceptance criteria

- A reviewer copy-pastes the README quickstart block on a fresh checkout and reaches a successful `yaao run` without consulting any other doc.
- Each `examples/*/` plan validates (`yaao validate`) cleanly.
- At least one example demonstrates each of: fan-out parallelism, per-task `merge: into`, monorepo `validation.cwd`.

## Tests

- `tests/phase-14/examples/validate.test.ts` — walks `examples/*/*.yaml`, asserts every plan passes `yaao validate` with zero errors.
- No execution test in CI (real agent binaries aren't available); the validity check is the load-bearing one.

## Out of scope

- A `yaao demo` CLI command. Not needed once the quickstart block exists.
- Pinned model versions in the examples — keep generic so they don't drift.
