# F14.1 `yaao doctor`

**Phase**: 14 — Release Polish
**Priority**: High
**Dependencies**: F1.3, F4.7, F7.1

## Goal

A single command that audits the user's environment and surfaces every actionable problem before they hit it during a real run.

## Checks

| Group | Check | Severity on fail |
|-------|-------|------------------|
| Runtime | Node ≥ 20 | error |
| Runtime | `git` ≥ 2.40 | error |
| Project | `.yaao/` exists | warning (run `yaao init`) |
| Project | `yaao.config.json` schema-valid | error |
| Project | No literal API keys in config | error |
| Project | All `${ENV}` refs resolvable | warning |
| Agents | Each enabled agent's CLI on PATH | warning per agent |
| Agents | Each enabled agent's version in supported range | warning |
| Agents | Copilot: `gh auth status` ok | warning |
| Agents | API: each provider has resolvable key | warning |
| ctx-sys | If enabled, `ctx-sys` on PATH | warning |
| ctx-sys | `.ctx-sys/` initialized in project | warning |
| ctx-sys | `ctx-sys serve` launches and responds to `tools/list` from each enabled backend | warning per backend |
| MCP | yaao's own MCP server starts in stdio mode and responds to `tools/list` | warning |
| Skills | Built-in skills installable for each enabled agent (dry run) | warning per agent |
| Disk | `.yaao/worktrees/` writable | error |
| Disk | Available disk space ≥ 5 × repo size on the worktree filesystem | warning |
| Git | Repo is clean enough to start a run (no in-progress merge/rebase) | warning |
| Runs | No orphaned runs (status=running but no live process) | warning per run |

## Strict Mode

`--strict`: warnings exit non-zero. Suitable for CI to block merges that would break local runs.

## Side Effects

- `--fix` attempts auto-fixes for a curated subset of issues:
  - Run `yaao init` if `.yaao/` missing.
  - Run `yaao skills install` if skills missing.
  - Refuses to install agent CLIs (out of scope; surfaces install commands).

## Orphan-run detection

Runs whose journal records `run:start` but never `run:end` derive to
`status: 'running'` forever. That's correct for in-flight runs, but
**also** what shows for runs killed by `kill -9`, a `yaao serve` crash
mid-`yaao_run`, or any failure path that doesn't go through the CLI's
SIGINT/SIGTERM handler (which already stamps `run:end status=cancelled`,
see `5a05f8c`). Workspace and `yaao_inspect` then show ghost "running"
runs that never finish.

The doctor (and the inspect-derived workspace status pill) treats a
run as orphaned when **all three** hold:

1. `summary.status === 'running'`
2. The journal hasn't been appended to in > 60 s (mtime heuristic — no
   live producer)
3. EITHER no `runner.pid` file exists in the run dir, OR the pid in
   that file fails `process.kill(pid, 0)` (i.e. the process is gone)

When orphaned, the doctor emits a warning per run and `yaao_inspect`
reports the run's derived status as `aborted` instead of `running` so
the web workspace pill doesn't lie. The journal file itself is not
mutated — orphan detection is a derivation, not a write. A user who
wants to permanently mark the run can call `yaao_prune` against it;
that already removes the run dir and the orphan goes away naturally.

Implementation note: the runner gets a small one-line add to write
`runDir/runner.pid` after `openJournal`. Sync write, no fsync needed —
on crash the file lingers but the alive-check catches that.

## Implementation Notes

- All checks run concurrently with a global timeout of 30 s.
- Agent probes reuse F4.7's cache.
- Each check is implemented as a `DoctorCheck` returning `{ severity, message, hint?, fix? }`.
- Orphan detection lives in a shared helper consumed by both doctor
  and the `yaao_inspect` workspace listing — single source of truth
  for "is this run actually alive?"

## Acceptance Criteria

- Output is deterministic (same env → same report) modulo timing.
- `--json` matches a stable schema used by `yaao web`'s `/api/health` endpoint (Phase 13).
- `--fix` only takes safe, reversible actions.
- Orphan-run detection: a run whose `runner.pid` is dead AND journal mtime > 60 s old reports as `aborted` in `yaao_inspect`, and as a warning in `yaao doctor`. A genuinely in-flight run (recent journal write) is never flagged.
