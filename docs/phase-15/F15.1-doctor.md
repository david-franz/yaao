# F15.1 `yaao doctor`

**Phase**: 13 — Distribution & Polish
**Priority**: High
**Dependencies**: F1.3, F4.7, F7.1

## Goal

A single command that audits the user's environment and surfaces every actionable problem before they hit it during a real run.

## Checks

| Group | Check | Severity on fail |
|-------|-------|------------------|
| Runtime | Node ≥ 20 | error |
| Runtime | `git` ≥ 2.40 | error |
| Project | `.yaao/` exists | warning (run `yaao init`) |
| Project | `yaao.config.json` schema-valid | error |
| Project | No literal API keys in config | error |
| Project | All `${ENV}` refs resolvable | warning |
| Agents | Each enabled agent's CLI on PATH | warning per agent |
| Agents | Each enabled agent's version in supported range | warning |
| Agents | Copilot: `gh auth status` ok | warning |
| Agents | API: each provider has resolvable key | warning |
| ctx-sys | If enabled, `ctx-sys` on PATH | warning |
| ctx-sys | `.ctx-sys/` initialized in project | warning |
| ctx-sys | `ctx-sys serve` launches and responds to `tools/list` from each enabled backend | warning per backend |
| MCP | yaao's own MCP server starts in stdio mode and responds to `tools/list` | warning |
| Skills | Built-in skills installable for each enabled agent (dry run) | warning per agent |
| Disk | `.yaao/worktrees/` writable | error |
| Disk | Available disk space ≥ 5 × repo size on the worktree filesystem | warning |
| Git | Repo is clean enough to start a run (no in-progress merge/rebase) | warning |

JSON mode (`--json`): emits a structured `DoctorReport`.

## Strict Mode

`--strict`: warnings exit non-zero. Suitable for CI to block merges that would break local runs.

## Side Effects

- `--fix` attempts auto-fixes for a curated subset of issues:
  - Run `yaao init` if `.yaao/` missing.
  - Run `yaao skills install` if skills missing.
  - Refuses to install agent CLIs (out of scope; surfaces install commands).

## Implementation Notes

- All checks run concurrently with a global timeout of 30 s.
- Agent probes reuse F4.7's cache.
- Each check is implemented as a `DoctorCheck` returning `{ severity, message, hint?, fix? }`.

## Acceptance Criteria

- Output is deterministic (same env → same report) modulo timing.
- `--json` matches a stable schema used by `yaao serve`'s health endpoint (Phase 14).
- `--fix` only takes safe, reversible actions.
