# F3.1 Worktree Manager

**Phase**: 3 — Worktree & Git Engine
**Priority**: Critical
**Dependencies**: F1.3, F1.5, F3.3

## Goal

Manage the lifecycle of one git worktree per task: create, populate, hand to the agent, tear down. The orchestration layer (Phase 5) calls this; nothing else mutates worktrees.

## Layout

```
.yaao/worktrees/<run-id>/<task-id>/
```

`<run-id>` is a short nanoid generated when `yaao run` starts. `<task-id>` is the plan's task ID. Both segments are slug-safe.

## API

```typescript
// src/git/worktree-manager.ts
export interface WorktreeRequest {
  runId: string;
  taskId: string;
  branch: string;             // e.g. "oauth/api"
  baseBranch: string;         // branch to fork from (resolved by F3.2)
  parentBranches: string[];   // additional branches to merge in (diamonds)
  rootDir: string;            // repo root
  worktreeRoot: string;       // .yaao/worktrees by default
}

export interface Worktree {
  taskId: string;
  branch: string;
  path: string;               // absolute worktree path
  baseCommit: string;         // sha of the commit the worktree was created at
}

export interface WorktreeManager {
  create(req: WorktreeRequest): Promise<Worktree>;
  remove(taskId: string, opts?: { force?: boolean }): Promise<void>;
  list(): Promise<Worktree[]>;
  get(taskId: string): Promise<Worktree | undefined>;
  pruneOrphans(): Promise<string[]>;     // cleanup leftovers from prior runs
}
```

## Create Sequence

1. **Validate**: ensure `rootDir` is a git repo with a clean working tree (or at least no conflicts in tracked files; uncommitted changes outside the worktree dirs are fine).
2. **Resolve base**: `git rev-parse --verify <baseBranch>`. Error if missing.
3. **Branch**: `git branch <branch> <baseBranch>` (fail if branch already exists; caller decides whether to recover).
4. **Worktree**: `git worktree add <path> <branch>`.
5. **Merge parents** (for diamonds): for each `parentBranch`, `git merge --no-ff --no-edit <parentBranch>` inside the worktree. If conflict, abort and propagate `WorktreeMergeError` carrying the conflict file list.
6. **Stamp**: write `.yaao/.task` inside the worktree containing `{ runId, taskId, baseCommit }` so we can identify orphans later.
7. Return the `Worktree` object.

## Remove Sequence

1. `git worktree remove <path>` (or `--force` if requested).
2. `git branch -D <branch>` if the policy says delete branches (controlled by caller; `yaao clean` exposes a flag).
3. Best-effort recursive `rm -rf` of the path if `git worktree remove` fails because of leftover untracked files (only with `force: true`).

## Orphan Pruning

`pruneOrphans()` scans `worktreeRoot` for directories with `.yaao/.task` whose `runId` isn't in the active runs registry, and removes them. Called once at the start of every `yaao run`.

## Concurrency

The manager assumes only one yaao process operates on a given repo at a time (a `.yaao/.lock` file is acquired by the runner in Phase 5). Within a single process, `create()` calls are safe in parallel; the underlying `git worktree add` is atomic per-path.

## Acceptance Criteria

- Creating a worktree from `main` produces a working dir at the expected path on the requested branch.
- A diamond (two parents) merges both into the worktree; clean merges succeed silently.
- A conflicting parent merge raises `WorktreeMergeError` and leaves the worktree in a recoverable state (no half-merged state on disk).
- `remove()` is idempotent — calling it twice doesn't fail.
- `pruneOrphans()` removes leftovers without touching active runs.
