# F3.4 Run State Journal

**Phase**: 3 — Worktree & Git Engine
**Priority**: High
**Dependencies**: F1.3, F2.1

## Goal

Append-only on-disk journal of every run. Enables `yaao run --resume`, `yaao status <run-id>`, and forensics after crashes.

## Storage

- File path: `.yaao/runs/<run-id>.jsonl`.
- One JSON event per line (NDJSON), `fsync`'d on every write.
- A sidecar `.yaao/runs/<run-id>.summary.json` is rewritten in place after every event with derived state (current task statuses, run start/end). Reading the summary is O(1); replaying the journal is the source of truth.

## Event Shape

```typescript
// src/git/journal.ts
export type JournalEvent =
  | { t: 'run:start';        time: string; runId: string; planFile: string; planHash: string; config: SerializedConfigSubset }
  | { t: 'task:queued';      time: string; taskId: string; depends: string[] }
  | { t: 'task:ready';       time: string; taskId: string }
  | { t: 'task:running';     time: string; taskId: string; agent: string; model?: string; worktree: string; branch: string; pid: number }
  | { t: 'task:output';      time: string; taskId: string; stream: 'stdout' | 'stderr'; chunk: string }   // optional, off by default for size
  | { t: 'task:completed';   time: string; taskId: string; durationMs: number; filesChanged: number; commit: string }
  | { t: 'task:failed';      time: string; taskId: string; durationMs: number; error: { code: string; message: string } }
  | { t: 'task:skipped';     time: string; taskId: string; reason: 'depFailed' | 'filtered' }
  | { t: 'merge:start';      time: string; taskId: string; into: string }
  | { t: 'merge:conflict';   time: string; taskId: string; files: string[] }
  | { t: 'merge:resolved';   time: string; taskId: string; by: 'auto' | 'agent' | 'manual'; commit: string }
  | { t: 'run:end';          time: string; status: 'success' | 'failed' | 'cancelled'; durationMs: number };
```

## Journal API

```typescript
export interface RunJournal {
  runId: string;
  append(event: JournalEvent): Promise<void>;
  read(): AsyncIterable<JournalEvent>;
  summary(): Promise<RunSummary>;
  close(): Promise<void>;
}

export function openJournal(runId: string, opts: { dir: string }): Promise<RunJournal>;
export function listRuns(dir: string): Promise<RunSummary[]>;
export function loadRun(runId: string, dir: string): Promise<{ events: JournalEvent[]; summary: RunSummary }>;
```

## Summary Shape

```typescript
export interface RunSummary {
  runId: string;
  planFile: string;
  planHash: string;             // sha256 of resolved plan; resume requires match
  startedAt: string;
  endedAt?: string;
  status: 'running' | 'success' | 'failed' | 'cancelled';
  tasks: Record<string, {
    status: 'pending' | 'ready' | 'running' | 'completed' | 'failed' | 'skipped';
    agent?: string;
    branch?: string;
    durationMs?: number;
    error?: { code: string; message: string };
  }>;
}
```

## Resume Semantics

- `yaao run --resume <id>` loads the journal, computes per-task status, and starts only `pending`/`ready`/failed-with-retries-remaining tasks.
- Resume refuses if the plan file's hash differs from `planHash` — the user must `--force` to acknowledge that the plan changed.
- Worktrees from prior runs are reused if their `.yaao/.task` matches; otherwise re-created.

## Size Management

- `task:output` events are off by default (`--journal-output` to enable). The TUI consumes events from the in-memory bus, not the journal.
- Journals older than N days (config: `journal.retention-days`, default 30) are pruned by `yaao clean --runs`.

## Acceptance Criteria

- Every run produces a journal with at least `run:start` and `run:end` events.
- After a `kill -9` mid-run, `loadRun(...)` reconstructs accurate task statuses.
- `--resume` only re-runs incomplete tasks; completed task worktrees are reused if intact.
- Plan hash mismatch on resume requires `--force`.
