# F9.4 Feature vs Project Scope

**Phase**: 9 — yaao-planner Skill
**Priority**: High
**Dependencies**: F9.1, F9.2

## Goal

The skill produces plans of two distinct shapes:
- `feature` — one file, 3-12 tasks, single subgraph.
- `project` — directory of phase files, up to 60 tasks across many subdirectories.

This feature pins the differences and the heuristics that decide which to emit when scope is ambiguous.

## `feature` Scope

- One file: `.yaao/plans/<slug>.md`.
- Single phase implicit (no phase headings).
- Tasks 3-12.
- All tasks live in the same DAG; commonly 1-3 layers deep.
- Suitable when the user's description fits in 1-2 sentences and targets an existing codebase.

## `project` Scope

- Directory: `.yaao/plans/<slug>/`.
- One `00-overview.md` plus N phase files.
- Each phase contains its own subgraph of tasks; cross-phase dependencies are explicit.
- Up to 60 tasks total; the planner is instructed to split further phases when the cap is approached.
- Suitable for green-field projects, multi-package monorepos, or migrations spanning weeks.

## Auto-detection Heuristic

When the user runs `yaao plan "..."` without `--scope`, the skill infers:
- description ≤ 200 chars and mentions one specific feature → `feature`.
- description ≥ 1000 chars, mentions architecture / multiple modules / "from scratch" → `project`.
- Otherwise: ask the user via stdout (interactive) or default to `feature` (non-TTY).

## Cap Enforcement

- `feature` plans with > 12 tasks → planner is instructed to either drop scope or upgrade to `project`.
- `project` plans approaching 60 tasks → planner adds a final phase listing "deferred" tasks rather than expanding indefinitely.

These caps are rules of thumb; the user can override with `--max-tasks <n>` (rarely needed).

## Why caps?

Plans that grow unbounded become unrunnable. A 200-task plan is an essay, not a build. The caps push the user (or the planner) toward decomposition: phase the work, run a phase, regenerate the next.

## Acceptance Criteria

- `feature` and `project` produce distinct file layouts.
- Auto-detection works in the obvious cases.
- The cap warnings fire and produce sensible behavior (not silent truncation).
