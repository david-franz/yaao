# F9.5 `yaao plan` Command

**Phase**: 9 — yaao-planner Skill
**Priority**: High
**Dependencies**: F9.1 - F9.4, F4 (agent backends), F7 (ctx-sys)

## Goal

The CLI driver. Resolves the planner skill, picks an agent, runs the agent with the right inputs, writes the resulting plan files.

## CLI

```
yaao plan <description> \
  [--scope feature|project] \
  [--format markdown|speckit|both] \
  [--agent <name>] \
  [--model <name>] \
  [--out <path>] \
  [--no-ctx-sys] \
  [--dry-run] \
  [--non-interactive]
```

Defaults:
- `--agent`: from `defaults.agent`.
- `--scope`: auto-detect (F9.4).
- `--format`: from `plan.format` config.
- `--out`: `.yaao/plans/`.

## Steps

1. Load config and resolve the planner skill.
2. Resolve the agent (or fail with a clear list of available agents).
3. If ctx-sys is enabled and not running, auto-spawn (F7.1).
4. Build the prompt: substitute the `{{description}}`, `{{scope}}`, `{{format}}`, `{{out}}` placeholders into the planner skill body.
5. Spawn the agent (F4) with the planner skill as `skills: [yaao-planner]`. The MCP config (F7.2) injects ctx-sys.
6. Stream agent output to the user (TUI or text logs).
7. After the agent exits successfully, expect the plan file(s) to exist on disk where the skill said it would write them.
8. Validate the produced plan with the F9.2 / F9.3 parser; print a summary and the path(s).

## Auto-validation

After the agent completes, yaao runs the plan parser on the output. If parsing fails:
- The error is shown.
- `yaao plan --retry` re-runs with the parser error appended to the prompt as feedback. Up to 2 retries by default (configurable).

## Dry-run

`--dry-run` prints the resolved skill prompt and the agent that would be invoked, without spawning. Useful for debugging skill content.

## Non-interactive Mode

`--non-interactive` disables the auto-detection prompt (F9.4) and any user-confirmation steps; all defaults are taken. Suitable for CI.

## Output

Text mode:
```
✔ generated plan
  .yaao/plans/oauth2-login.md  (9 tasks, 3 layers, ctx-sys: 4 queries)

next:
  yaao convert .yaao/plans/oauth2-login.md
```

JSON mode (`--json`):
```json
{ "ok": true, "files": [".yaao/plans/oauth2-login.md"], "tasks": 9, "queriedCtxSys": 4 }
```

## Acceptance Criteria

- A working end-to-end run with the fake agent backend produces a parseable plan.
- Auto-validation catches malformed plans.
- `--dry-run` makes no FS changes.
- ctx-sys is auto-spawned when configured.
