# F9.3 Spec Kit Format Support

**Phase**: 9 — yaao-planner Skill
**Priority**: Medium
**Dependencies**: F9.2

## Goal

Allow `yaao-planner` to emit GitHub Spec Kit-compatible plan triplets (`spec.md` + `plan.md` + `tasks.md`), so users embedded in the Spec Kit workflow can use yaao without changing their tooling.

## Output Layout

```
.yaao/plans/<slug>/spec.md
.yaao/plans/<slug>/plan.md
.yaao/plans/<slug>/tasks.md
```

(or, with `--out specs/<slug>/`, anywhere the user wants).

## Files

### `spec.md`

The "what and why" — high-level intent. yaao-planner produces this from the user's `description` and ctx-sys context. Format follows the upstream Spec Kit conventions current at release time (header, user stories, acceptance criteria).

### `plan.md`

The "how" — architectural sketch, key components, sequencing. yaao-planner emits this with phase headings and bullets.

### `tasks.md`

The granular task list. yaao's converter reads this file primarily.

```markdown
# Tasks

- [ ] T001 Scaffold project — depends: ∅
- [ ] T002 Implement REST API — depends: T001
- [ ] T003 Implement UI — depends: T001
- [ ] T004 E2E tests — depends: T002, T003
```

The converter (F10.3) maps each `- [ ] Tnnn` line to a task. The `depends: ` clause is parsed (Spec Kit-compatible). Task prompts are pulled from per-task subsections in `plan.md` (`## T001 — …`) and from `spec.md` references.

## Configuration

```json
"plan": { "format": "speckit" }
```

or per-invocation: `yaao plan "..." --format speckit`. With `--format both`, both the markdown and Spec Kit forms are written; the converter prefers markdown when both exist (consistent default).

## Compatibility Caveats

- yaao tracks the upstream Spec Kit format conventions at release time. If the format shifts, yaao adds a `--speckit-version` flag.
- yaao's task-prompt extraction relies on heading conventions; if upstream changes those, the converter degrades gracefully (warns rather than errors).

## Acceptance Criteria

- Emitting in `speckit` format produces three files that pass an upstream-compatibility smoke test (parsing them with a known Spec Kit example fixture).
- `--format both` produces markdown + speckit triplets that the converter agrees on.
- Round-trip produces stable output.
