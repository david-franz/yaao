# F10.5 Default Agent Assignment

**Phase**: 10 — yaao-converter Skill
**Priority**: High
**Dependencies**: F10.1

## Goal

Assign a sensible `agent:` (and optionally `model:`) to each task when the input plan didn't specify one. Heuristic-based and configurable.

## Order of Precedence

For each task, the converter chooses:
1. The task's `suggestedAgent` from the plan IR (if the plan author wrote one).
2. The matching rule from `convert.agent-rules` in `yaao.config.json`.
3. The project's `defaults.agent`.

## Configurable Rules

```json
"convert": {
  "agent-rules": [
    { "match": { "title-regex": "(?i)test|spec" },         "agent": "codex" },
    { "match": { "title-regex": "(?i)ui|frontend|page" },  "agent": "cursor", "model": "auto" },
    { "match": { "files-glob": "infra/**" },               "agent": "claude-code", "model": "opus" },
    { "match": { "any": true },                            "agent": "claude-code", "model": "opus" }
  ]
}
```

Rules are evaluated top-to-bottom; first match wins. The final `any: true` rule is the catch-all.

## Match Predicates

| Predicate | Description |
|-----------|-------------|
| `title-regex` | Case-sensitive regex against `task.title`. |
| `id-regex` | Same against `task.id`. |
| `files-glob` | Any of `task.files` matches the glob. |
| `prompt-contains` | Plain substring in `task.prompt` (case-insensitive option). |
| `any: true` | Always matches; used as the catch-all. |

## Built-in Defaults

If the user has no `agent-rules`, yaao ships sensible defaults:
- Tests → `codex`.
- UI / frontend → `cursor`.
- Everything else → `claude-code` with the project's default model.

These can be turned off (`convert.agent-rules.use-defaults: false`).

## API Backend Assignment

When a task has `suggestedAgent: api` (or matches a rule for `agent: api`), the converter must also resolve a provider/model. It uses `convert.api-defaults`:

```json
"convert": {
  "api-defaults": { "provider": "anthropic", "model": "claude-opus-4-7" }
}
```

If the resolved provider has no API key, the converter emits a warning and demotes the task to the global `defaults.agent` instead of producing a plan that will fail at run time.

## Manual Override

Even after assignment, the user can edit the YAML. The converter never claims to be authoritative — it produces a starting point.

## Acceptance Criteria

- Plans without suggestions get sensible defaults.
- Rules apply top-to-bottom; the first match wins.
- Missing API keys cause demotion + warning, not a silently broken plan.
- Built-in defaults can be disabled.
