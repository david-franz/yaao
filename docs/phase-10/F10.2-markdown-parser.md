# F10.2 Markdown Plan Parser

**Phase**: 10 — yaao-converter Skill
**Priority**: Critical
**Dependencies**: F9.2

## Goal

Deterministic parser for the markdown plan format defined in F9.2 — both yaao-authored plans and reasonably-shaped hand-authored ones. Produces an intermediate representation (IR) the converter skill operates on.

## IR

```typescript
// src/converter/ir.ts
export interface PlanIR {
  meta: { name: string; scope: 'feature' | 'project'; description?: string };
  tasks: TaskIR[];
  files: PlanFileIR[];          // per phase file when project-scope
  source: SourceMap;
}

export interface TaskIR {
  id: string;
  title: string;
  prompt: string;                // assembled from prose + ### Files + ### Validation
  depends: string[];             // declared in the table (no inference here)
  suggestedAgent?: AgentName;
  suggestedModel?: string;
  files?: string[];
  validation?: { command: string; mustPass: boolean };
  source: { file: string; headingLine: number };
}
```

## Parsing

- Use `remark` (+ `remark-frontmatter`) to walk the AST.
- Locate the **Tasks** table by heading. Parse its rows as the authoritative task index.
- For each task, find the `## <id> — <title>` heading and collect:
  - All paragraphs/blockquotes until the next `## ` (excluding `### ` subsections).
  - `### Files` items (bulleted list) into `files`.
  - `### Validation` line into `validation`.
- Cross-check: every table row has a heading; warn (not error) if a heading lacks a row.

## Project-scope Handling

- `00-overview.md` is parsed first; it lists phase files in a numbered list under `## Phases`.
- Each phase file is parsed in order. Task IDs must be globally unique; duplicates produce an error.
- Cross-phase dependencies declared in `## Cross-phase dependencies` are merged into the per-task `depends:` field.

## Hand-authored Plans

Real-world plans rarely look exactly like F9.2. The parser tolerates:
- Missing **Tasks** table — falls back to scanning `## ` headings; the converter skill (F10.1) gets a warning to consider.
- Missing `### Files` / `### Validation` — silently absent in IR.
- Different heading levels — accepted as long as they're consistent.

What the parser refuses:
- Files that aren't markdown.
- Files with no recognizable task structure (warns, returns empty `tasks`).

## Source Maps

Every IR node carries a `source` pointer for downstream errors. When the converter writes YAML and validation fails, errors point back to the original markdown.

## Acceptance Criteria

- A canonical F9.2 plan parses to IR with all tasks, deps, suggested agents, files, validation.
- A hand-authored plan with a partial structure parses with the recognizable parts.
- Cross-phase deps are merged correctly.
- Duplicate task IDs across phase files raise an error.
