# F10.3 Spec Kit Plan Parser

**Phase**: 10 — yaao-converter Skill
**Priority**: Medium
**Dependencies**: F10.2, F9.3

## Goal

Parse a Spec Kit triplet (`spec.md` + `plan.md` + `tasks.md`) into the same `PlanIR` the markdown parser produces.

## Inputs

The parser is invoked with a directory path. It locates:
- `tasks.md` — required.
- `plan.md` — preferred for prompt detail.
- `spec.md` — used for top-level metadata and as a fallback context source.

## Mapping

### `tasks.md`

```markdown
# Tasks

- [ ] T001 Scaffold — depends: ∅
- [ ] T002 API — depends: T001
```

- Each `- [ ] T<nnn> <Title>` line becomes a task with `id = T<nnn>` (lowercase normalized when downstream slug rules require it; the IR keeps the original).
- `depends: T001, T002` parsed from the `— depends:` clause; `∅` or missing means none.
- The line itself becomes `title`. Prompt is assembled from the per-task subsection of `plan.md` (`## T001 — …`).

### `plan.md`

- Top-level structure provides architectural context — combined into `meta.description`.
- Per-task subsections under `## T001 — …` populate the prompt body.

### `spec.md`

- Header → `meta.name`, `meta.description`.
- User-story / acceptance-criteria sections aren't directly mapped to tasks but are appended to the plan-level metadata for the converter skill to use as background.

## Compatibility

Spec Kit's exact format evolves. The parser:
- Targets the conventions current at release time.
- Permits surrounding text (acceptance criteria, notes) without choking.
- Surfaces a `version` warning if the file format looks newer/older than expected.

## Mixed Plans

If the user has *both* a yaao-format markdown plan and a Spec Kit triplet for the same slug, the converter prefers the markdown form (per F9.3 docs). The Spec Kit parser is a separate code path used when `--from speckit` is passed or the input directory lacks a markdown plan.

## Acceptance Criteria

- A Spec Kit fixture parses to IR with all tasks and dependencies.
- Per-task prompts from `plan.md` are correctly attached.
- Loosely-structured Spec Kit files (extra sections, missing acceptance criteria) still parse.
- A version mismatch produces a warning, not an error.
