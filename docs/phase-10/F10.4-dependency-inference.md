# F10.4 Dependency Inference

**Phase**: 10 — yaao-converter Skill
**Priority**: Medium
**Dependencies**: F10.2, F10.3

## Goal

When the input plan has *some* explicit dependencies and *some* missing, infer the missing ones from prose cues — but only when the inference is high-confidence. Always surface inferred deps for user review.

## Default Behavior

By default the converter does **not** infer deps. The execution plan reflects exactly what the input plan declared. This is the safest baseline.

## Optional Inference

`yaao convert <plan> --infer-deps` activates inference. Or the user can configure it project-wide in `yaao.config.json`:

```json
"convert": { "infer-deps": "suggest" }
```

Modes:
- `off` — never infer.
- `suggest` — infer and emit, but mark each inferred dep with a comment in the YAML and require explicit user confirmation (`yaao convert --apply-inferred`).
- `auto` — infer and apply silently (highest risk; only enable when you trust your prose).

## Heuristics

The skill is given a tool `infer_deps(taskA: TaskIR, taskB: TaskIR) → Confidence` that scores whether `B` plausibly depends on `A`. Implementation candidates:
- **Lexical cues** — phrases in `B`'s prompt: "uses the API from", "after", "depends on", "requires", "extends".
- **Reference matching** — if `B`'s prose mentions files/symbols that `A` is responsible for creating.
- **Domain heuristics** — tests depend on the things they test; UIs depend on the APIs they call.

The skill aggregates confidence across heuristics. Threshold defaults to 0.7; configurable via `convert.infer-deps.threshold`.

## Output

In `suggest` mode, inferred deps appear with comments:

```yaml
- id: integration-tests
  depends:
    - api          # explicit
    - ui           # inferred (confidence 0.83 — "tests fetch from /posts" matches api)
```

The user reviews and runs `yaao convert --apply-inferred .yaao/exec/plan.yaml` to commit them, or removes the inferred lines.

## Cycle Avoidance

Inferred deps that would introduce a cycle are dropped (not silently — they appear in the warnings).

## Acceptance Criteria

- Default behavior matches input dependencies exactly.
- `suggest` mode produces annotated output the user can audit.
- `auto` is opt-in and well-documented.
- No inferred dep ever introduces a cycle.
