# F8.4 Copilot Skill Emitter

**Phase**: 8 — Skills System (MCP-first)
**Priority**: High
**Dependencies**: F8.1, F12.1, F12.5

## Goal

Register yaao's MCP server in Copilot's MCP config and append a short managed block to `.github/copilot-instructions.md` describing each yaao skill. As with the other emitters, skill bodies live once in yaao's MCP server, not duplicated here.

## Output Layout

```
.github/
└── copilot-instructions.md      # managed blocks per skill
.vscode/
└── mcp.json                     # workspace MCP config (or wherever the active Copilot version reads from)
```

### `.github/copilot-instructions.md` (managed block per skill)

```markdown
<!-- yaao-managed: yaao-planner@1 -->
## yaao-planner (yaao MCP)

Generate an implementation plan from a description. Use MCP tool `yaao_skill_yaao-planner` with `{ description, scope?, format? }`.
<!-- /yaao-managed: yaao-planner@1 -->
```

The emitter respects existing user content; it only writes/updates content between its delimiters.

### Workspace MCP Config

Copilot's MCP config location and format have moved across recent versions. The emitter targets the version range yaao's F4.4 backend supports and reads `agents.copilot.mcp-config-path` from `yaao.config.json` to override when needed (default: `.vscode/mcp.json`).

```json
{
  "servers": {
    "yaao": {
      "type": "stdio",
      "command": "yaao",
      "args": ["serve", "--stdio"]
    }
  }
}
```

The yaao block is delimited inside the `servers` object so user entries are preserved.

## No Per-skill Prompt Files

Earlier versions of this design wrote `.github/prompts/<name>.prompt.md` per skill with the full body. That's gone — the body lives in yaao's MCP server. The Copilot backend (F4.4) calls into the MCP tool directly when the agent invokes it. For Copilot versions where MCP coverage is incomplete, F4.4 falls back to inlining the skill body at spawn time, sourced from `.yaao/skills/<name>/prompt.md`.

## Idempotency

- One delimited `yaao` entry in the MCP config; user entries preserved.
- One managed block per skill in `copilot-instructions.md`; user content outside blocks preserved.
- Removing a skill removes its block; the MCP server entry stays as long as any yaao skill exists.

## Acceptance Criteria

- Multiple skills' managed blocks coexist with each other and with user-authored content.
- Pre-existing user MCP server entries in the workspace MCP config are preserved.
- Removing a skill cleans up cleanly.
- Copilot-spawned agents call the yaao MCP tools end-to-end.
- The MCP-config path is configurable for forward compatibility with new Copilot versions.
