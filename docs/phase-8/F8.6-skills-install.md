# F8.6 `yaao skills install` & Sync

**Phase**: 8 — Skills System
**Priority**: High
**Dependencies**: F8.1 - F8.5

## Goal

The user-facing command to materialize source-of-truth skills as agent-specific artifacts, plus `sync` and `validate` subcommands.

## CLI

```
yaao skills install [<name>...] \
  [--agent <name>]              # only emit for one agent
  [--user]                      # write to ~/.yaao/skills emitters (user-global)
  [--force]                     # overwrite hand-edited files

yaao skills sync                # like install but only re-emits changed
  [--remove <name>]             # delete a skill's emitted artifacts
  [--prune]                     # remove emitted artifacts for skills no longer in source

yaao skills validate [<name>...]
yaao skills list
```

## `install` Behavior

1. Discover skills:
   - Specific names if provided.
   - Otherwise, all skills under `.yaao/skills/` (and `~/.yaao/skills/` if `--user`).
   - Plus the two built-in skills (yaao-planner, yaao-converter) — always installed unless `skills.builtin.enabled: false`.
2. Validate each (F8.1 schema).
3. For each skill, for each agent in `appliesTo.agents` ∩ enabled-agents-in-config:
   - Run the corresponding emitter (F8.2-F8.5).
   - Print a one-line per-file result.
4. Print a summary table.

## `sync` vs `install`

- `install` writes everything (with hash-equality short-circuit per emitter).
- `sync` is the same thing rebranded — it's intended to be cheap and idempotent and is what `yaao init` and post-config-change hooks call.
- `sync --prune` additionally removes artifacts for skills that no longer exist in the source. Without `--prune`, leftovers are reported as warnings.

## `list` Output

```
$ yaao skills list
name             version   source              emits-for
yaao-planner     1         (built-in)          claude-code, cursor, copilot, codex
yaao-converter   1         (built-in)          claude-code, cursor, copilot, codex
my-team-style    1         .yaao/skills/...    claude-code, cursor
```

## `validate` Output

Reports schema issues and unresolved placeholders, file-by-file. Exit 0 if all clean.

## Concurrency / Locking

`yaao skills install` takes the same `.yaao/.lock` as `yaao run` (they conflict — installing during a run could pull artifacts out from under in-flight agents). The lock is held only for the duration of the install.

## Acceptance Criteria

- A fresh `yaao init` followed by `yaao skills install` produces a working set of skill artifacts for every enabled agent.
- Re-running `install` after a skill body change re-emits only the changed skill.
- `--prune` removes artifacts for deleted skills; without it, only warnings.
- `validate` catches malformed `skill.yaml` and undefined placeholders.
