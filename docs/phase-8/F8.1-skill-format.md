# F8.1 Skill Source-of-truth Format

**Phase**: 8 — Skills System
**Priority**: High
**Dependencies**: F1.3

## Goal

A single canonical format for a "skill" that yaao exposes as an MCP tool (`yaao_skill_<name>`) and lightly references in per-agent config files. Author once; the MCP server (Phase 12) makes it available to every connected agent.

This is an MCP-first design: the skill body lives **once** behind yaao's MCP boundary. Per-agent emitters (F8.2-F8.5) write thin bootstraps and instruction stubs, not duplicated skill bodies.

## Layout

```
.yaao/skills/<skill-name>/
├── skill.yaml         # metadata + applies-to + tools
├── prompt.md          # the instruction body
└── examples/          # optional; few-shot examples
    └── *.md
```

## `skill.yaml`

```yaml
name: yaao-planner
version: 1
description: Generate implementation plans from a description
appliesTo:
  agents: [claude-code, cursor, copilot, codex, api]   # which to emit for
  globs: ['**/*']                                      # for editor auto-attach (Cursor)
tools:                                                 # advisory; agents that allow tool gating use this
  - read_file
  - write_file
  - context_query                                      # ctx-sys
inputs:                                                # for parameterized invocation
  - name: description
    description: What to plan
    required: true
  - name: scope
    description: feature | project
    required: false
    default: feature
trigger:                                               # when the skill should auto-fire (Claude Code skills, Cursor rules)
  manual: true                                         # always require explicit invocation
  matchPath: ['.yaao/plans/**']                        # editor auto-attach
```

## `prompt.md`

A markdown file with the skill body. Conventions:
- Use `{{description}}` / `{{scope}}` placeholders for declared inputs.
- Sections recognized by the emitters:
  - `## System` — becomes the system prompt for API backends; included verbatim for CLI agents.
  - `## Examples` — optional few-shot examples (also pulled from `examples/`).
  - `## Constraints` — translated into "you must / you must not" lines.

## Skill Resolution

`skills: [yaao-planner]` in a task is resolved against:
1. `.yaao/skills/<name>/`
2. `~/.yaao/skills/<name>/` (user-global skills)
3. Built-in: `<package>/dist/skills/<name>/` (yaao-planner, yaao-converter ship here)

First match wins. The resolver returns the loaded skill plus its origin path for diagnostics.

## Validation

`yaao skills validate [name]` checks:
- `skill.yaml` parses against the Zod schema.
- All declared inputs are referenced in `prompt.md`.
- `appliesTo.agents` contains only known agent names.
- No `prompt.md` longer than 10 KB unless `--allow-large` (long prompts hurt cache rates and confuse models).

## Acceptance Criteria

- A minimal skill (just `name`, `description`, `prompt.md` body) loads and emits.
- Built-in `yaao-planner` and `yaao-converter` skills ship with the package.
- Resolution precedence (project > user > built-in) works.
- Schema validation has positive and negative tests.
