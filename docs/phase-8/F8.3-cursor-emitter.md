# F8.3 Cursor Skill Emitter

**Phase**: 8 — Skills System (MCP-first)
**Priority**: High
**Dependencies**: F8.1, F12.1, F12.5

## Goal

Register yaao's MCP server in Cursor and add a short managed block describing each yaao skill — nothing more. The skill body lives once in yaao's MCP server.

## Output Layout

```
.cursor/
├── mcp.json                     # managed `yaao` server entry
└── rules/
    └── yaao.mdc                 # one file with managed blocks for each skill (always-on, small)
```

### `.cursor/mcp.json`

A managed `yaao` entry is added/replaced in the user's `mcp.json` (preserving any other entries). The managed block is delimited:

```json
{
  "mcpServers": {
    // ... user entries left untouched ...
    "yaao": {                                  // managed by yaao
      "command": "yaao",
      "args": ["serve", "--stdio"]
    }
  }
}
```

### `.cursor/rules/yaao.mdc`

```mdc
---
description: yaao MCP tools available in this workspace
alwaysApply: true
---

<!-- yaao-managed: yaao-planner@1 -->
## yaao-planner

Generate an implementation plan from a description. Use MCP tool `yaao_skill_yaao-planner` with `{ description, scope?, format? }`.
<!-- /yaao-managed: yaao-planner@1 -->

<!-- yaao-managed: yaao-converter@1 -->
## yaao-converter

Convert an implementation plan into an execution plan. Use MCP tool `yaao_skill_yaao-converter` with `{ input, out?, split? }`.
<!-- /yaao-managed: yaao-converter@1 -->
```

This is *one* always-applied rule file with one block per skill, not one rule per skill. Smaller footprint, easier to reason about. Cursor sees that the yaao MCP tools exist and what each does at a one-line level.

## Inline Fallback

For Cursor versions where MCP is unavailable, F4.3 inlines skill bodies into the prompt at spawn. The emitter never writes per-skill `.mdc` files with full prompt bodies — that's handled at backend spawn time when needed.

## Idempotency

- The `yaao` block in `mcp.json` is delimited and replaced in place.
- Per-skill blocks in `yaao.mdc` are delimited and replaced in place.
- Removing a skill removes only its block.
- Hand-edits between yaao's delimiters are detected; the emitter refuses to overwrite without `--force`.

## Acceptance Criteria

- A pre-existing `.cursor/mcp.json` with user entries is preserved bit-for-bit outside the yaao block.
- A round-trip emits identical bytes.
- A skill not applicable to Cursor produces no block.
- Cursor agent spawns can call the yaao MCP tools end-to-end.
