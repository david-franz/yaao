# F8.5 Codex Skill Emitter

**Phase**: 8 — Skills System
**Priority**: High
**Dependencies**: F8.1

## Goal

Surface yaao skills to Codex via `AGENTS.md` (Codex's standard skill / instruction surface).

## Outputs

- Project root `AGENTS.md` — append a managed block per skill.
- Optional per-subdirectory `AGENTS.md` files when `skill.yaml.appliesTo.dirs` is set (Codex resolves `AGENTS.md` hierarchically).

## Block Format

```markdown
<!-- yaao-managed: <name>@<version> -->
## <name>

<rendered prompt.md, possibly trimmed for size>
<!-- /yaao-managed: <name>@<version> -->
```

## Why Append to `AGENTS.md` Rather Than Multiple Files?

Codex doesn't have a multi-file skill format yet. `AGENTS.md` is its canonical instruction surface. Multiple skills share the file, each in its own block. The F4.5 backend additionally inlines the active skill's body into the prompt at spawn time, so even if `AGENTS.md` grows long, the model is explicitly directed at the right block.

## Size Management

If a skill's `prompt.md` exceeds `codex.skill.max-size` (default 4 KB), the emitter writes a *summary* block in `AGENTS.md` and stores the full prompt in `.yaao/skills/<name>/prompt.md` (already the source). The F4.5 backend reads the full prompt at spawn and inlines it. This keeps `AGENTS.md` browsable while preserving fidelity at runtime.

## Idempotency

Same managed-block pattern as F8.4. Removing a skill removes the block. Hand-edited blocks are detected.

## Acceptance Criteria

- Multiple yaao skill blocks coexist with each other and with user-authored `AGENTS.md` content.
- Per-subdirectory `AGENTS.md` files are written only when `appliesTo.dirs` is set.
- Large skills produce a summary block in `AGENTS.md` and rely on backend-side inlining for fidelity.
- Removal cleans up.
