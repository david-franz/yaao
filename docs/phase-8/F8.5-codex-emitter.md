# F8.5 Codex Skill Emitter

**Phase**: 8 — Skills System (MCP-first)
**Priority**: High
**Dependencies**: F8.1, F12.1, F12.5

## Goal

Register yaao's MCP server with Codex via a per-run TOML overlay, and append a short managed block per skill to `AGENTS.md`. Skill bodies are not duplicated here — they live in yaao's MCP server.

## Output Layout

```
AGENTS.md                                # managed block per skill (project root)
.yaao/codex-mcp-overlay.toml             # generated TOML overlay applied via --config at spawn time
```

### `AGENTS.md` Block (per skill)

```markdown
<!-- yaao-managed: yaao-planner@1 -->
## yaao-planner

Generate an implementation plan. Call MCP tool `yaao_skill_yaao-planner` with `{ description, scope?, format? }`.
<!-- /yaao-managed: yaao-planner@1 -->
```

Per-subdirectory `AGENTS.md` files are emitted only when `skill.yaml.appliesTo.dirs` is set (Codex resolves `AGENTS.md` hierarchically).

### TOML Overlay (per run, ephemeral)

```toml
[mcp_servers.yaao]
command = "yaao"
args = ["serve", "--stdio"]
```

The F4.5 backend passes this overlay via `--config` at spawn time. The user's persistent `~/.codex/config.toml` is never modified.

## No Inlined Prompt Bodies in `AGENTS.md`

Earlier versions of this design embedded full skill bodies in `AGENTS.md`. That's gone. `AGENTS.md` carries one-paragraph descriptors and pointers to the MCP tools; the bodies live behind the MCP boundary.

For Codex versions where MCP integration is unavailable, F4.5 inlines the skill body into the prompt at spawn time, sourced from `.yaao/skills/<name>/prompt.md`. Configurable via `agents.codex.mcp: 'preferred' | 'forced' | 'fallback-only'`.

## Idempotency

- Per-skill blocks in `AGENTS.md` are delimited and replaced in place.
- The TOML overlay is regenerated per run; never persists.
- Removing a skill removes its block.
- Hand-edits between yaao's delimiters are detected.

## Acceptance Criteria

- Multiple yaao skill blocks coexist with each other and with user-authored `AGENTS.md` content.
- Per-subdirectory `AGENTS.md` files are written only when `appliesTo.dirs` is set.
- The TOML overlay never persists past the spawn; `~/.codex/config.toml` is untouched.
- Codex-spawned agents call the yaao MCP tools end-to-end.
