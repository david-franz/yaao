# F8.2 Claude Code Skill Emitter

**Phase**: 8 — Skills System (MCP-first)
**Priority**: High
**Dependencies**: F8.1, F12.1, F12.5

## Goal

Make yaao's MCP server discoverable to Claude Code. The skill body itself is exposed as the MCP tool `yaao_skill_<name>` (Phase 12); this emitter writes only the small bootstrap files Claude Code needs to find that server and know it's there.

## Output Layout (small, MCP-first)

```
.claude/
├── yaao-mcp.json                # MCP server registration (managed by yaao)
└── CLAUDE.md                    # managed block per skill (one short paragraph each)
```

### `yaao-mcp.json`

```json
{
  "mcpServers": {
    "yaao": {
      "command": "yaao",
      "args": ["serve", "--stdio"]
    }
  }
}
```

The yaao backend (F4.2) passes `--mcp-config .claude/yaao-mcp.json` per spawn (or merges it with the per-spawn ctx-sys config from F7.2).

### `CLAUDE.md` Block (per skill)

```markdown
<!-- yaao-managed: yaao-planner@1 -->
## yaao-planner

Generate an implementation plan from a description. Call the MCP tool `yaao_skill_yaao-planner` with `{ description, scope?, format? }`.
<!-- /yaao-managed: yaao-planner@1 -->
```

That's it. No SKILL.md, no agents/, no inlined prompt body. The body lives in yaao's MCP server and is fetched at tool-call time.

## When the Inline Fallback is Used

If the user's Claude Code version doesn't speak MCP for some reason (extremely old, unusual sandbox), F4.2's backend falls back to inlining the skill body via `--append-system-prompt`. This emitter doesn't generate that artifact — it lives at spawn time in the backend layer, sourced directly from `.yaao/skills/<name>/prompt.md`. Configurable via `agents.claude-code.mcp: 'preferred' | 'forced' | 'fallback-only'`.

## Idempotency

- Each managed block in `CLAUDE.md` is keyed by `<name>@<version>` and replaced in place.
- `yaao-mcp.json` is regenerated wholesale; user content outside it (the user's own `.claude/mcp.json`, etc.) is untouched.
- Removing a skill removes only its block. The `yaao-mcp.json` server registration stays as long as any yaao skills exist; a final `yaao skills sync --remove-all` cleans up the file too.

## Acceptance Criteria

- A round-trip is hash-stable: emit twice, get the same bytes.
- Hand-edited `CLAUDE.md` content outside managed blocks is preserved.
- A skill with `appliesTo.agents` excluding `claude-code` is not emitted.
- Claude Code spawned via F4.2 successfully calls `yaao_skill_<name>` and receives the prompt body from yaao's MCP server.
