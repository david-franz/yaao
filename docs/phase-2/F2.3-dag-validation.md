# F2.3 DAG Validation

**Phase**: 2 — Plan Schema & Validation
**Priority**: Critical
**Dependencies**: F2.1, F2.2

## Goal

Beyond schema validation, prove the plan is *executable* before we touch the filesystem. Cycles, dangling refs, duplicate IDs, impossible parallelism, and unknown agent/model references all caught here.

## Public API

```typescript
// src/plan/validate/index.ts
export interface ValidationIssue {
  severity: 'error' | 'warning';
  code: string;                                  // e.g. YAAO_PLAN_CYCLE
  message: string;
  location?: { file: string; line: number; col: number };
  taskId?: string;
  hint?: string;
}

export function validatePlan(
  plan: ResolvedPlan,
  source: SourceMap,
  ctx: { config: YaaoConfig; agents: AgentAvailability }
): ValidationIssue[];
```

`agents` (from F4.7) lets the validator distinguish "agent disabled in config" (error) from "agent enabled but not installed locally" (warning unless `yaao validate --strict`).

## Checks

| Code | Severity | Description |
|------|----------|-------------|
| `YAAO_PLAN_DUPLICATE_TASK_ID` | error | Two tasks share an ID. |
| `YAAO_PLAN_CYCLE` | error | Dependency cycle; lists the cycle. |
| `YAAO_PLAN_MISSING_DEP` | error | `depends:` references an unknown task. |
| `YAAO_PLAN_SELF_DEP` | error | Task depends on itself. |
| `YAAO_PLAN_DUPLICATE_BRANCH` | error | Two tasks pin the same branch name. |
| `YAAO_PLAN_DUPLICATE_WORKTREE` | error | Two tasks pin the same worktree path. |
| `YAAO_PLAN_PROMPT_REF_MISSING` | error | `prompt-ref` path doesn't exist. |
| `YAAO_PLAN_AGENT_DISABLED` | error | Task uses an agent disabled in `yaao.config.json`. |
| `YAAO_PLAN_AGENT_NOT_INSTALLED` | warning | Backend reachable per config but binary not on PATH. |
| `YAAO_PLAN_API_NO_KEY` | error | `agent: api` but provider has no resolvable key. |
| `YAAO_PLAN_SKILL_UNKNOWN` | warning | Skill name doesn't resolve under `.yaao/skills/`. |
| `YAAO_PLAN_FAN_OUT_HIGH` | warning | Width of any DAG layer > `max-parallel * 4` (likely unintended). |
| `YAAO_PLAN_NO_TASKS` | error | Plan has no tasks. |
| `YAAO_PLAN_UNREACHABLE_TASK` | warning | Task has no incoming dependencies and no incoming `--only` filter — fine, but flagged in strict mode. |
| `YAAO_PLAN_MERGE_NONE_WITH_DEPS` | warning | Task with `merge: none` is depended on by another task — downstream may not see its work after the run ends. |

## Cycle Detection

Tarjan's strongly-connected-components on the task graph. Any SCC of size > 1, or any self-edge, is reported with the full cycle path:

```
YAAO_PLAN_CYCLE: cycle detected: api → tests → migrations → api
  - api          (oauth.yaml:12)
  - tests        (oauth.yaml:34)
  - migrations   (oauth.yaml:48)
```

## Output Modes

- Programmatic: returns `ValidationIssue[]` (empty = valid).
- CLI (F2.4): pretty-prints grouped by severity with file/line links; exit code 0 if no errors, 1 otherwise. `--json` emits the issue array.

## Strict Mode

`--strict` promotes all warnings to errors. Useful in CI.

## Acceptance Criteria

- Every check above has a positive (issue raised) and negative (clean plan) test.
- Cycle detection terminates on graphs with thousands of tasks.
- Validation is deterministic — issues sorted by `(file, line, col, code)`.
- Validation is pure — no filesystem mutation, no network, no agent invocation.
