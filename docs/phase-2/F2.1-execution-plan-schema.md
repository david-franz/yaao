# F2.1 Execution Plan Schema

**Phase**: 2 — Plan Schema & Validation
**Priority**: Critical
**Dependencies**: F1.3

## Goal

A single canonical schema for execution plans, expressed in Zod and exported to JSON Schema for editor IntelliSense. Every other phase consumes this type.

## Top-level Shape

```yaml
plan:
  name: string                  # required, slug-friendly
  version: 1                    # required
  description: string?          # optional human description

config:
  base-branch: string?          # default: from yaao.config.json
  max-parallel: integer?        # default: from yaao.config.json
  worktree-root: string?        # default: from yaao.config.json
  merge:
    strategy: auto | pr | manual
    on-conflict: manual | agent

context:
  ctx-sys:
    enabled: bool?
    require-query: bool?

includes:                       # optional sub-plan refs (relative paths)
  - ./phases/01-api.yaml
  - ./phases/02-ui.yaml

tasks:
  - <Task>
```

## Task Schema

```yaml
- id: string                    # unique within the plan, slug
  title: string
  description: string?
  prompt: string?               # inline prompt body
  prompt-ref: string?           # path to a .md file holding the prompt (mutually exclusive with `prompt`)
  depends: [string]?            # task IDs this depends on
  agent: claude-code | cursor | copilot | codex | api
  model: string?
  api:
    provider: anthropic | openai | openrouter
    model: string
    base-url: string?
  skills: [string]?             # skill names; resolved against .yaao/skills/
  files: [string]?              # glob hints (advisory, not enforced)
  branch: string?               # default: <plan-name>/<task-id>
  worktree: string?             # override path; default under worktree-root
  timeout: duration?            # e.g. "30m"; cancels the agent
  retries: integer?             # default 0
  validation:
    command: string?            # shell command run in the worktree post-completion
    must-pass: bool?            # if true, non-zero exit fails the task; default true
  merge: auto | pr | manual | none?       # default: from config.merge
  context:                      # per-task ctx-sys overrides
    ctx-sys:
      enabled: bool?
      require-query: bool?
  env:                          # extra env vars passed to the agent process
    KEY: value
```

## Zod Sketch

```typescript
// src/plan/schema/plan.ts
export const TaskSchema = z.object({
  id: z.string().min(1).regex(/^[a-z][a-z0-9-_]*$/),
  title: z.string().min(1),
  description: z.string().optional(),
  prompt: z.string().optional(),
  'prompt-ref': z.string().optional(),
  depends: z.array(z.string()).default([]),
  agent: AgentSchema,
  model: z.string().optional(),
  api: ApiBindingSchema.optional(),
  skills: z.array(z.string()).default([]),
  files: z.array(z.string()).default([]),
  branch: z.string().optional(),
  worktree: z.string().optional(),
  timeout: DurationSchema.optional(),
  retries: z.number().int().min(0).default(0),
  validation: ValidationSchema.optional(),
  merge: z.enum(['auto', 'pr', 'manual', 'none']).optional(),
  context: ContextSchema.optional(),
  env: z.record(z.string()).default({}),
}).refine(t => Boolean(t.prompt) !== Boolean(t['prompt-ref']),
  { message: 'task requires exactly one of prompt or prompt-ref' });

export const PlanSchema = z.object({
  plan: z.object({ name: z.string(), version: z.literal(1), description: z.string().optional() }),
  config: PlanConfigSchema.optional(),
  context: ContextSchema.optional(),
  includes: z.array(z.string()).default([]),
  tasks: z.array(TaskSchema).default([]),
});

export type Plan = z.infer<typeof PlanSchema>;
export type Task = z.infer<typeof TaskSchema>;
```

## Default Resolution

The schema is *partial* — many fields are optional. A separate **resolver** (`src/plan/schema/resolve.ts`) merges in defaults from `yaao.config.json`, producing a `ResolvedPlan` where every field needed for execution is concrete. Distinguishing the two prevents silent drift if defaults change.

## JSON Schema Export

A build step runs `zod-to-json-schema` and writes `schema/execution-plan.schema.json`. The published npm package ships this artifact; users can reference it in their YAML via:

```yaml
# yaml-language-server: $schema=https://yaao.dev/schema/execution-plan.json
plan:
  name: my-plan
```

## Acceptance Criteria

- The schema validates the example plans in `examples/` (added in this phase).
- `prompt` xor `prompt-ref` is enforced.
- Unknown top-level keys are rejected (strict mode) but unknown task fields under `env:` are allowed.
- The exported JSON Schema validates the same examples when fed through `ajv`.
- `ResolvedPlan` is fully concrete: no optional fields after resolution.
