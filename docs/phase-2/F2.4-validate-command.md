# F2.4 `yaao validate` Command

**Phase**: 2 — Plan Schema & Validation
**Priority**: High
**Dependencies**: F2.1, F2.2, F2.3

## Goal

The user-facing entrypoint to plan validation. Fast, deterministic, CI-friendly.

## CLI

```
yaao validate <exec-plan> [--strict] [--json] [--no-resolve]
```

- `<exec-plan>`: path to the YAML plan (or directory; if directory, validates every `*.yaml` plan found at the top level).
- `--strict`: warnings become errors, exit 1.
- `--json`: emit the `ValidationIssue[]` array as JSON to stdout; logger output goes to stderr.
- `--no-resolve`: skip default-resolution against `yaao.config.json`; validate only what's literally in the file. Useful for CI checking shared plans without environment-specific defaults.

## Output (text)

```
✘ .yaao/exec/oauth.yaml — 2 errors, 1 warning

  ✘ YAAO_PLAN_CYCLE   cycle detected: api → tests → api
      .yaao/exec/oauth.yaml:12: api
      .yaao/exec/oauth.yaml:34: tests

  ✘ YAAO_PLAN_AGENT_DISABLED   task 'frontend' uses 'cursor' but agent is disabled
      .yaao/exec/oauth.yaml:58
      hint: enable cursor in .yaao/yaao.config.json (agents.cursor.enabled = true)

  ⚠ YAAO_PLAN_AGENT_NOT_INSTALLED   task 'codegen' uses 'codex' but binary not on PATH
      .yaao/exec/oauth.yaml:71
      hint: install with `npm i -g @openai/codex` or set agents.codex.enabled = false
```

## Output (json)

```json
{
  "plan": ".yaao/exec/oauth.yaml",
  "ok": false,
  "issues": [
    { "severity": "error",   "code": "YAAO_PLAN_CYCLE", ... },
    { "severity": "error",   "code": "YAAO_PLAN_AGENT_DISABLED", ... },
    { "severity": "warning", "code": "YAAO_PLAN_AGENT_NOT_INSTALLED", ... }
  ]
}
```

## Exit Codes

| Code | Meaning |
|------|---------|
| 0 | No errors (warnings allowed unless `--strict`). |
| 1 | One or more errors (or warnings in `--strict`). |
| 2 | Could not load the plan (parse error, file not found). |

## Performance Targets

- A 100-task plan validates in < 50 ms on a recent laptop.
- A 5000-task plan validates in < 2 s.
- The validator does no IO beyond reading the plan files and the config; agent availability is queried via the F4.7 cache.

## Acceptance Criteria

- A clean plan exits 0 silently in `--json`, prints `✔ ok` in text mode.
- A plan with errors exits 1 and prints all issues (does not bail at the first).
- `--strict` promotes warnings, behaves identically otherwise.
- Directory mode validates each plan independently; aggregates the exit code (1 if any plan fails).
