# F2.2 YAML Parser & Loader

**Phase**: 2 — Plan Schema & Validation
**Priority**: Critical
**Dependencies**: F2.1

## Goal

Load an execution plan (and any sub-plans referenced via `includes:`) from disk, parse it, and produce a single resolved `Plan` object with source-position metadata for downstream error messages.

## API

```typescript
// src/plan/yaml/loader.ts
export interface LoadOptions {
  cwd: string;
  config: YaaoConfig;
  maxIncludeDepth?: number;       // default 8
}

export interface LoadResult {
  plan: ResolvedPlan;
  files: LoadedFile[];            // every file read, in load order
  source: SourceMap;              // task.id -> { file, line, col }
}

export async function loadPlan(planPath: string, opts: LoadOptions): Promise<LoadResult>;
```

## File Resolution

- `planPath` is resolved against `opts.cwd`.
- `includes:` paths are resolved relative to the *including* plan's directory.
- Includes are loaded recursively. Each task in an included plan is namespaced by the include's `plan.name` if a collision would occur (warned, not auto-prefixed silently).

## Source Maps

Use `yaml`'s `parseDocument` to retain CST/AST information. Walk the AST to record `(file, line, col)` for every task and surface it via `result.source`. Validators in F2.3 use this to produce errors like:

```
.yaao/exec/oauth.yaml:42:7: task 'verify-tokens' depends on missing task 'create-tokens'
```

## Cycle Detection (Across Files)

Includes form a graph. Reject cycles with a typed `IncludeCycleError` listing the cycle path. Reject depth >= `maxIncludeDepth` with `IncludeDepthError`.

## Merging Semantics

- `tasks` arrays from included plans are concatenated, preserving order.
- `config` and `context` from the top-level plan win over included plans on conflict; included plans' values fill in only where the top-level is silent.
- Duplicate task IDs across files: the loader collects all, the validator (F2.3) reports the duplicates.

## Error Surface

All errors are `YaaoError` subclasses:

- `PlanNotFoundError` — file missing.
- `PlanParseError` — YAML syntax error (wraps `yaml`'s error with file + position).
- `IncludeCycleError`, `IncludeDepthError`.
- `PlanValidationError` (raised after Zod parse fails).

## Acceptance Criteria

- A single-file plan loads and matches `ResolvedPlan` exactly.
- A plan with two `includes:` loads with all tasks present, in include order.
- Source map points each task back to its origin file/line.
- Cyclic includes raise `IncludeCycleError` with the cycle listed.
- Syntax errors report file + line + column.
