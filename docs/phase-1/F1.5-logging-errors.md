# F1.5 Logging & Error Handling

**Phase**: 1 — Foundation
**Priority**: High
**Dependencies**: F1.1

## Goal

A structured logger and a typed error hierarchy used across yaao. No `console.*` in library code; no untyped `throw new Error('...')` for user-visible failures.

## Logger

```typescript
// src/log/logger.ts
export interface Logger {
  trace(msg: string, fields?: Record<string, unknown>): void;
  debug(msg: string, fields?: Record<string, unknown>): void;
  info(msg: string, fields?: Record<string, unknown>): void;
  warn(msg: string, fields?: Record<string, unknown>): void;
  error(msg: string, fields?: Record<string, unknown>): void;
  child(bindings: Record<string, unknown>): Logger;
}

export interface LoggerOptions {
  level: 'trace' | 'debug' | 'info' | 'warn' | 'error';
  format: 'text' | 'json';
  stream?: NodeJS.WritableStream;       // default: stderr
}

export function createLogger(opts: LoggerOptions): Logger;
```

- Text format is human-friendly with colors when stderr is a TTY (`chalk`).
- JSON format is one line per event with `time`, `level`, `msg`, `runId?`, `taskId?`, plus user fields.
- `--verbose` => level=debug; `--quiet` => level=warn; `--json` => format=json.
- `child()` clones the logger with bound fields (e.g. `taskId`).

## Error Hierarchy

```typescript
// src/log/errors.ts
export class YaaoError extends Error {
  readonly code: string;
  readonly hint?: string;
  readonly cause?: unknown;
  constructor(opts: { code: string; message: string; hint?: string; cause?: unknown });
}

// User-actionable subclasses (each has a stable `code`):
export class NotInitializedError       extends YaaoError {} // YAAO_NOT_INITIALIZED
```

## Top-level Error Handler

```typescript
// src/bin/yaao.ts
yaao(process.argv).then(
  code => process.exit(code),
  err => {
    if (err instanceof YaaoError) {
      logger.error(err.message, { code: err.code });
      if (err.hint) logger.error(`hint: ${err.hint}`);
      process.exit(1);
    }
    logger.error('unexpected error', { err });
    process.exit(99);
  }
);
```

- Known errors (`YaaoError`) exit 1 and print message + hint, no stack trace by default.
- `--verbose` adds the stack and the cause chain.
- Unknown errors exit 99 and always print the stack.

## Hint Catalogue

Each `code` has a default hint (overridable). Examples:
- `YAAO_NOT_INITIALIZED` → `Run 'yaao init' to scaffold this project.`
- `YAAO_LITERAL_SECRET` → `Replace the literal value with '${ENV_VAR}' or move it to .yaao/secrets.local.json.`
- `YAAO_MISSING_ENV` → `Set the env var <name> in your shell or in .yaao/secrets.local.json.`

## Acceptance Criteria

- No `console.*` calls in `src/` outside of `src/bin/yaao.ts` (enforced by an ESLint rule).
- All thrown errors crossing a public API boundary inherit from `YaaoError`.
- `--json` output is line-delimited JSON parseable by `JSON.parse` per line.
- Unknown errors exit 99; known errors exit 1.
