# F1.4 `yaao init` Command

**Phase**: 1 — Foundation
**Priority**: Critical
**Dependencies**: F1.1, F1.2, F1.3

## Goal

Scaffold a usable yaao project in one command. After `yaao init` the user has every directory, every default file, and a configured `.gitignore` ready to go.

## Behavior

```
$ yaao init [--force] [--cwd <path>] [--minimal]
```

Creates (idempotently — never overwrites without `--force`):

```
.yaao/
├── yaao.config.json            # default config (F1.3 schema)
├── secrets.local.json          # `{ "agents": { "api": { "providers": {} } } }`
├── plans/                      # empty
├── exec/                       # empty
├── skills/                     # empty (populated by F8)
├── worktrees/                  # empty + .gitkeep
└── runs/                       # empty + .gitkeep
```

Edits:

- `.gitignore`: appends a managed block (delimited by `# >>> yaao` / `# <<< yaao`) listing `.yaao/secrets.local.json`, `.yaao/worktrees/`, `.yaao/runs/`. Idempotent — re-running `init` doesn't duplicate the block.

Flags:

- `--force` — overwrite existing files in `.yaao/` (still doesn't touch user-authored content outside `.yaao/`).
- `--minimal` — skip the gitignore block; useful for non-git workflows.
- `--cwd <path>` — initialize a different directory.

## Default `yaao.config.json`

```json
{
  "$schema": "https://yaao.dev/schema/config.json",
  "version": 1,
  "defaults": {
    "agent": "claude-code",
    "model": "opus",
    "max-parallel": 4,
    "base-branch": "main",
    "worktree-root": ".yaao/worktrees"
  },
  "merge": { "strategy": "auto", "on-conflict": "manual" },
  "agents": {
    "claude-code": { "enabled": true },
    "cursor":      { "enabled": true },
    "copilot":     { "enabled": true },
    "codex":       { "enabled": true },
    "api": { "providers": {} }
  },
  "ctx-sys": { "enabled": false, "auto-spawn": true, "require-query": false },
  "plan": { "format": "markdown", "speckit": false }
}
```

## Output

Prints a tree of files created and a follow-up hint:

```
✔ Initialized yaao in /path/to/repo/.yaao
  • yaao.config.json
  • secrets.local.json
  • added managed block to .gitignore

Next steps:
  1. yaao agents              # see which agents are available
  2. yaao plan "describe what you want to build"
```

## Edge Cases

- Already initialized, no `--force`: prints "already initialized" and exits 0 (idempotent).
- Not a git repo: still works — only the `.gitignore` step is skipped with a warning.
- No write permission: typed `InitWriteError` with the offending path.
- Pre-existing managed gitignore block: replaced in place if `--force`, otherwise left alone.

## Acceptance Criteria

- Running `yaao init` twice in a row succeeds both times with no diff after the second run.
- `yaao init --force` resets `.yaao/yaao.config.json` to the default exactly.
- `.gitignore` block is added once even across many `init` calls.
- Empty/non-git directory: `init` succeeds, gitignore step warns rather than fails.
- After `init`, `yaao --help` is unchanged but `loadConfig()` reads the new project config.
