# F1.2 CLI Skeleton & Command Registry

**Phase**: 1 — Foundation
**Priority**: Critical
**Dependencies**: F1.1

## Goal

Wire up `commander`, register every command in the v1 surface as a stub, and enforce a uniform command-module contract so each later phase plugs in cleanly.

## Command Module Contract

Every command lives in `src/cli/commands/<name>.ts` and exports:

```typescript
import type { Command } from 'commander';
import type { CliContext } from '../context.js';

export interface CommandModule {
  name: string;
  describe: string;
  register(program: Command, ctx: CliContext): void;
}
```

`CliContext` is built once per CLI invocation and threaded into every command:

```typescript
export interface CliContext {
  cwd: string;
  config: YaaoConfig;          // resolved by F1.3
  logger: Logger;              // F1.5
  env: NodeJS.ProcessEnv;
  exit: (code: number) => never;
}
```

This isolates commands from `process.*` and makes them trivially testable.

## Top-level CLI

```typescript
// src/cli/index.ts
export async function yaao(argv: string[] = process.argv): Promise<number> {
  const ctx = await buildContext();
  const program = new Command()
    .name('yaao')
    .description('yet another agent orchestrator')
    .version(VERSION);

  for (const mod of COMMAND_MODULES) {
    mod.register(program, ctx);
  }

  await program.parseAsync(argv);
  return 0;
}
```

`src/bin/yaao.ts` calls `yaao(process.argv).then(process.exit, ...)` and routes uncaught errors through F1.5.

## Conventions

- All commands accept `--cwd <path>` (defaults to `process.cwd()`) for testability.
- All commands accept `--json` to switch to machine-readable output.
- All commands accept `-v, --verbose` and `-q, --quiet` (mapped to logger levels in F1.5).
- A command that requires an initialized project must call `requireInitialized(ctx)` which throws a typed `NotInitializedError`.

## Acceptance Criteria

- `yaao --help` lists every command from the table above.
- Each stub command exits with code 2 and prints "not yet implemented (will land in phase N)".
- `yaao init` is the only command that fully works at this phase (per F1.4).
- Adding a new command is exactly: create the file, add to `COMMAND_MODULES`, write tests.

## Tests

- `tests/phase-1/cli/help.test.ts` — runs `yaao --help` and asserts each command appears in output.
- `tests/phase-1/cli/version.test.ts` — `yaao --version` matches package version.
- `tests/phase-1/cli/stubs.test.ts` — every non-init command exits 2 with the expected message.
- `tests/phase-1/cli/cwd-flag.test.ts` — `--cwd` is honored by `init`.
