# F5.2 Task Lifecycle & Event Bus

**Phase**: 5 — Execution Engine
**Priority**: Critical
**Dependencies**: F3.1, F3.4, F4.1, F5.1

## Goal

The orchestrator that ties the scheduler, worktree manager, agent backend, and journal together for a single task. Plus a global event bus that the TUI subscribes to.

## Lifecycle (per task)

1. **Queue** — emitted on scheduler init.
2. **Ready** — when deps complete.
3. **Provision worktree** — F3.1 creates the worktree; on failure, task fails immediately.
4. **Resolve prompt** — read `prompt-ref` if present; concatenate `context.md` artifacts from completed dependencies (F5.3).
5. **Spawn agent** — F4 backend; events streamed.
6. **Wait** — until completion, timeout, or external cancellation.
7. **Validation** — if `task.validation.command` is set, run it in the worktree; non-zero exit fails the task (unless `must-pass: false`).
8. **Capture diff** — record number of files changed, paths, and a short stat for the journal and TUI.
9. **Commit** — if the agent didn't commit, commit the working-tree changes with a generated message: `[<task-id>] <task-title>`.
10. **Notify scheduler** — `completeTask` or `failTask`.

## Event Bus

```typescript
// src/exec/lifecycle.ts
export type RunEvent =
  | SchedulerEvent
  | { type: 'task:agent-event'; taskId: string; ev: AgentEvent }
  | { type: 'task:diff';        taskId: string; filesChanged: number; insertions: number; deletions: number }
  | { type: 'task:committed';   taskId: string; sha: string }
  | { type: 'run:start';        runId: string; planFile: string }
  | { type: 'run:end';          runId: string; status: 'success' | 'failed' | 'cancelled' };

export interface RunBus {
  emit(ev: RunEvent): void;
  subscribe(fn: (ev: RunEvent) => void): () => void;
  asyncIterator(): AsyncIterable<RunEvent>;
}
```

Built on `eventemitter3` with a small queue per subscriber. The TUI consumes via `asyncIterator`. The journal consumes synchronously and writes events to disk.

## Cancellation Propagation

- `SIGINT` (Ctrl-C) flips run state to "cancelling": active tasks are cancelled (F4.1 `cancel()`), no new tasks start, partial work in worktrees is preserved.
- A second `SIGINT` becomes "force-cancel": `SIGKILL` agent processes immediately.
- `run:end` emits with `status: 'cancelled'`.

## Commit Detection

After the agent exits, the lifecycle inspects the worktree:
- If `git diff HEAD` is empty: nothing to commit; record outcome.
- If non-empty: stage all (subject to `.yaaoignore`) and commit with the auto message. The agent's transcript is added as the commit body for traceability.

## Validation Command

```yaml
validation:
  command: npm test
  must-pass: true
```

Run via `execa(opts.command, { cwd: worktree, shell: true })`. Output is captured into a `task:validation` event (not specified here for brevity but emitted). Non-zero exit fails the task.

## Acceptance Criteria

- A task with no agent diff still emits `task:committed` only if there's something to commit (otherwise `task:completed` carries `filesChanged: 0`).
- Validation failure is distinguished from agent failure in the error code.
- Ctrl-C cancels in-flight agents gracefully and produces a useful journal.
- Subscribers added after `run:start` still see backfilled events (the bus replays the last N or has a per-subscriber buffer).
