# F5.5 Run Modes (Resume, Filter, Dry-run, Force)

**Phase**: 5 — Execution Engine
**Priority**: High
**Dependencies**: F5.4, F3.4

## Goal

Make `yaao run` flexible enough for real-world iteration: resume from where you crashed, run only what you care about, preview without executing, and override the plan-hash safety net when you actually changed the plan on purpose.

## Modes

### Resume

```
yaao run <plan> --resume <run-id>
```

- Loads journal `<run-id>`.
- Compares the plan's resolved hash to the journal's `planHash`. Mismatch → `PlanHashMismatchError` unless `--force`.
- Initializes the scheduler with all already-`completed`/`failed`/`skipped` tasks marked terminal.
- Re-uses worktrees that still exist on disk and pass an integrity check (`.yaao/.task` matches expected `runId/taskId`).
- Worktrees missing or mismatched are recreated.

### Filter

```
yaao run <plan> --only <ids>
yaao run <plan> --skip <ids>
```

- See F5.1 for filter semantics.
- The run still produces a journal — partial runs are first-class.

### Dry Run

```
yaao run <plan> --dry-run
```

- Prints (or emits, with `--json`) the execution order, per-task agent/model/skill assignments, expected branch/worktree paths, and a parallelism histogram.
- Does **not** create worktrees, branches, or invoke agents.
- Does **not** write a journal (a `--journal-dry-run` flag exists for testing).

### Force

`--force` is the umbrella flag for accepting otherwise-blocking conditions:
- `--force` after `PlanHashMismatchError` — proceed anyway; the journal records that the plan changed.
- `--force-unlock` (separate flag) — remove a stale `.yaao/.lock`.

We deliberately keep these two separate so a single `--force` doesn't accidentally bypass two safety nets.

## Output

Dry-run text:

```
$ yaao run plan.yaml --dry-run

plan: my-feature           tasks: 7      max-parallel: 4
base-branch: main          worktree-root: .yaao/worktrees

execution order (topological):
  layer 1 [1]:  scaffold        (claude-code/opus)        worktree: …/scaffold
  layer 2 [2]:  api             (cursor)                  worktree: …/api
                ui              (api/anthropic claude-opus-4-7) worktree: …/ui
  layer 3 [1]:  integration     (codex)                   worktree: …/integration

est. parallelism width: 2 (limited by max-parallel=4 not reached)
```

## Interactions with `--resume`

`--resume` is composable:
- with `--only`/`--skip`: filter applies to the *remaining* tasks.
- with `--dry-run`: previews exactly what the resumed run would do.

## Acceptance Criteria

- `--resume` correctly skips completed tasks and re-runs failed ones (subject to retries).
- Plan-hash mismatch always blocks unless `--force`; the journal records the override.
- `--dry-run` is side-effect-free.
- `--only` + `--skip` together is rejected with a clear error.
