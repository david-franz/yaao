# F5.3 Context Passing Between Tasks

**Phase**: 5 — Execution Engine
**Priority**: High
**Dependencies**: F5.2

## Goal

When task `B` depends on task `A`, `B`'s agent should know what `A` did. Not the entire transcript — a useful, bounded summary.

## Producer: `context.md`

After each task completes, the lifecycle writes `.yaao/runs/<run-id>/<task-id>/context.md`:

```markdown
# <task-id> — <title>

**Branch**: oauth/api
**Files changed**: 12 (+412 / -8)

## Summary

<last 80 lines of the agent's stdout, deduplicated and trimmed>

## Files

- src/auth/oauth.ts          (added)
- src/auth/oauth.test.ts     (added)
- src/server.ts              (modified)
- ...

## Commit

abcdef1 [api] Implement REST API
```

For API-backend tasks the "Summary" section is replaced with the model's final assistant message, which is typically already a good summary.

## Consumer: prompt prefix injection

When task `B` is launched, its prompt is prefixed:

```
## Context from prior tasks

### task: scaffold (completed)
<inlined context.md>

### task: setup-models (completed)
<inlined context.md>

---

<B's actual prompt>
```

Inlining is bounded:
- Per-dep cap: 2,000 tokens (configurable via `task.context-budget-per-dep`).
- Total cap: 12,000 tokens; oldest deps trimmed first beyond cap.
- A note is appended when truncation occurred.

## Diamond Cases

If `B` depends on multiple tasks, each contributes a separate section. Order is topological-then-lexicographic.

## Why not full transcripts?

Transcripts are huge and noisy. The `context.md` pattern (proven in worktree-style runners) gives the next agent the answer to "what already exists?" without paying for the entire upstream conversation.

## ctx-sys Note

When `context.ctx-sys.enabled: true`, the prompt also gains a directive: "If you need code-level details about the upstream changes, call `context_query` (the upstream task's commit will already be visible in this branch)." This avoids stuffing diffs into the prompt when the agent can ask for them on demand.

## Acceptance Criteria

- `context.md` is written for every completed task.
- Token budgets are enforced; truncation is annotated, not silent.
- The prefix is deterministic — same inputs always produce the same prefix bytes.
- Skipped/failed dependencies do not contribute to the prefix.
