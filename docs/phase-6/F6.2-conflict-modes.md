# F6.2 Conflict Modes (manual / auto / agent)

**Phase**: 6 — Merge Engine
**Priority**: Critical
**Dependencies**: F6.1, F4.1

## Goal

When a merge produces conflicts, the resolution mode is configurable per project and per task: `manual` (default), `auto` (only if clean), or `agent` (a model resolves).

## Mode: `manual` (default)

- Orchestrator aborts the trial merge.
- Re-runs the merge non-trivially (`git merge --no-commit <task-branch>`) so conflicts are written to the working tree.
- Prints the conflicting file list and instructions:
  ```
  Conflict merging task 'api':
    src/server.ts
    src/auth.ts

  Options:
    - resolve manually, then run:  yaao merge --continue
    - skip this task:              yaao merge --skip api
    - abort and reset base:        yaao merge --abort
  ```
- Exits 1; the run journal records the unresolved conflict.

## Mode: `auto`

- *Never* commits a non-clean merge.
- If trial merge is clean, commits.
- If conflict, the merge is aborted and the task is recorded as conflicted with `mode: auto`. The user must re-invoke with a different mode to actually resolve.
- This mode exists because users sometimes want "merge if you can, otherwise tell me" without the side-effect of a working tree full of markers.

## Mode: `agent`

- Configured via:
  ```json
  "merge": {
    "on-conflict": "agent",
    "conflict-resolver": { "agent": "claude-code", "model": "sonnet" }
  }
  ```
- Steps:
  1. Re-run merge to populate conflict markers.
  2. Spawn the configured resolver agent in the repo root with a tightly-scoped prompt: "Resolve the conflicts in the following files. Do not modify anything outside these files. Run `git diff --check` after each edit."
  3. Pass the conflict file list and the diffs of both sides as context.
  4. After the agent exits:
     - Run `git diff --check` — if it reports leftover markers, the resolution failed.
     - Run any project-defined validation (tests configured at `merge.validation`).
  5. If validation passes, commit. Otherwise, abort the merge and treat as if the agent had failed.
- Agent resolutions are committed with a message annotating the resolver agent and model: `[merge-resolve] api into main (claude-code/sonnet)`.

## Per-task Override

A task can override the global mode:

```yaml
- id: rename-db-table
  merge: manual          # don't trust the agent on schema changes
```

## Safety Rails for `agent` Mode

- `git diff --check` enforced.
- Configurable hard ceiling on lines changed by the resolver (`merge.agent.max-lines`, default 200). Beyond that the resolution is rejected.
- Resolution runs in a scratch worktree (not the user's main worktree) so a runaway resolution never trashes the user's checkout.

## Acceptance Criteria

- `manual` is the default and is exercised in CI as the canonical path.
- `auto` never produces a commit with `<<<<<<<` markers.
- `agent` mode rejects resolutions that leave markers, exceed line ceilings, or fail validation.
- Per-task override beats the global setting.
