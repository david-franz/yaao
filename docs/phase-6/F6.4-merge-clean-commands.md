# F6.4 `yaao merge` & `yaao clean`

**Phase**: 6 — Merge Engine
**Priority**: High
**Dependencies**: F6.1, F6.2, F6.3

## Goal

User-facing commands for "merge what I just ran" and "tear down the worktrees from a run".

## `yaao merge`

```
yaao merge [run-id] \
  [--target <branch>] \
  [--mode auto|manual|agent] \
  [--dry-run] \
  [--continue] \
  [--skip <task-id>] \
  [--abort] \
  [--pr]                 # force PR mode for tasks not marked otherwise
```

- If `run-id` is omitted, uses the most recent finished run.
- `--target` overrides the base branch from the plan/config.
- `--mode` overrides the on-conflict mode for this invocation.
- `--continue`, `--skip`, `--abort` operate on a previously paused merge (manual conflict).
- `--dry-run` shows the merge plan without touching git.
- `--pr` upgrades all `auto` tasks to `pr` for this invocation (e.g., when CI policy changes).

## Pause / Resume Semantics

When `manual` mode hits a conflict:
- The orchestrator stops, leaves the working tree with conflict markers, and writes `.yaao/runs/<run-id>/merge-state.json` describing what's resolved/pending.
- `yaao merge --continue` reads that state, expects the user to have resolved the conflict, runs `git diff --check`, commits, and proceeds.
- `yaao merge --skip <task-id>` aborts the in-flight merge (`git merge --abort`), removes that task from the resumable plan, and continues.
- `yaao merge --abort` resets the base branch to the pre-merge HEAD (recorded in `merge-state.json`) and removes the state file.

## `yaao clean`

```
yaao clean [run-id] \
  [--all]                # all completed runs
  [--worktrees-only]     # don't touch branches
  [--branches-only]      # don't touch worktrees
  [--keep-failed]        # default true: don't delete worktrees from failed/cancelled runs
  [--force]              # required to clean unmerged work
  [--runs <days>]        # also prune journals older than N days
```

Defaults to a *cautious* clean:
- Removes worktrees of tasks that were merged (or PRs created and closed/merged).
- Leaves worktrees of unmerged tasks alone.
- Leaves journals alone unless `--runs` is given.

`--force` overrides the unmerged-work safety net. The command always confirms interactively unless `--yes`.

## Acceptance Criteria

- `yaao merge` and `yaao merge --continue` form a complete loop for the manual-resolution path.
- `yaao clean` never deletes unmerged work without `--force`.
- `yaao clean --all` cleans every finished run's artifacts, leaves any in-flight run's untouched.
- `--dry-run` on both commands is read-only.
