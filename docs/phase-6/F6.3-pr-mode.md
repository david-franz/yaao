# F6.3 PR Merge Mode

**Phase**: 6 — Merge Engine
**Priority**: High
**Dependencies**: F6.1, F3.3

## Goal

For tasks marked `merge: pr`, push the task branch to the configured remote and open a PR via `gh pr create`. Don't merge locally.

## Configuration

Per-task:
```yaml
- id: api
  merge: pr
```

Globally:
```json
"merge": { "strategy": "pr" }
```

If global is `pr` and a task overrides to `auto`, that one task is merged locally.

## Steps

1. Check `gh` is installed and authenticated (re-uses the F4.4 probe).
2. `git push <remote> <branch>` (with `--set-upstream` on first push).
3. Detect the existing PR for the branch via `gh pr view <branch> --json url,state`. If one exists and is open, skip creation; record the URL.
4. Otherwise, create:
   ```
   gh pr create \
     --base <baseBranch> \
     --head <branch> \
     --title "[yaao] <task.title>" \
     --body  <generated body>
   ```
5. Add the URL to the run journal (`merge:pr-created` event).

## PR Body Template

```
Generated by yaao for task `<task-id>` (run `<run-id>`).

**Plan**: `<plan-name>`
**Agent**: `<agent>` (`<model>`)
**Files changed**: 12 (+412 / -8)

## Summary

<task description from the plan>

## Files

- src/auth/oauth.ts (added)
- src/auth/oauth.test.ts (added)
- ...

## Linked tasks

- depends on: scaffold (#PR or branch)
```

The "depends on" section links to upstream PRs when those tasks were also `merge: pr`, otherwise references the branch by name.

## Remote Configuration

- Remote name from `git remote` (default `origin`); overridable via `merge.pr.remote` config.
- The branch name pushed is the same as the task branch (`<plan>/<task-id>`).
- A `merge.pr.draft: true` config opens PRs as drafts.

## Failure Modes

- Push fails (auth, network): orchestrator records failure for the task and continues with other PR tasks.
- `gh pr create` fails: same.
- A failure in PR mode does not block local-merge tasks from continuing.

## Acceptance Criteria

- A clean repo with `gh` authenticated produces a PR for each `merge: pr` task.
- Re-running `yaao merge` is idempotent — already-open PRs are detected, not duplicated.
- Auth missing produces a clear error; the run journal records it.
