# F11.2 `yaao view` (Static)

**Phase**: 11 — TUI
**Priority**: High
**Dependencies**: F2.1, F11.1

## Goal

Open an execution plan in a static interactive viewer. Inspect the DAG, drill into tasks, see merge/agent/skill details — without executing.

## CLI

```
yaao view <exec-plan> [--no-tui]
```

`--no-tui` falls back to a textual print of the resolved plan.

## Modes

- **Graph mode** (default) — DAG renderer fills the screen; right-side panel shows the selected task's full config.
- **Table mode** (`v` toggles) — `status-table` (without status) showing per-task agent, model, skills, files, branch, deps.
- **Detail mode** (`enter`) — full-screen view of the selected task: prompt body, file globs, validation command, ctx-sys settings.

## Keybindings

```
[↑↓ jk]    select task
[v]        toggle graph / table
[enter]    show task detail
[esc]      back
[/]        filter (substring on id/title)
[q]        quit
```

## Programmatic Mode (`--no-tui`)

Prints a tree summary suitable for piping:

```
$ yaao view plan.yaml --no-tui
plan: my-feature   tasks: 7   layers: 3   max-parallel: 4

L1: scaffold (claude-code/opus)            files: package.json, tsconfig.json, src/**
L2: api      (cursor)        ← scaffold
    ui       (api/anthropic) ← scaffold    model: claude-opus-4-7
L3: integration (codex)      ← api, ui     merge: pr
```

## Validation

`yaao view` runs F2.3 validation before rendering and overlays errors/warnings as banner rows. The viewer never refuses to open a partially-valid plan — it shows what it can.

## Acceptance Criteria

- Graph mode is usable on a 100×30 terminal for plans up to 30 tasks.
- Table mode supports sort and filter.
- Detail mode displays multi-paragraph prompts with proper wrapping.
- `--no-tui` produces deterministic text output suitable for snapshot tests.
