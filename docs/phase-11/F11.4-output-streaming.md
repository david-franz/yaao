# F11.4 Agent Output Streaming

**Phase**: 11 — TUI
**Priority**: High
**Dependencies**: F4.1, F5.2, F11.3

## Goal

Surface agent output to the TUI in real time, not in a batch dump after each task completes.

## Pipeline

```
AgentBackend.spawn → AgentProcess.events (AsyncIterable<AgentEvent>)
   ↓
TaskWorker (F5.2) re-emits as bus event { type: 'task:agent-event', taskId, ev }
   ↓
RunBus subscribers: TUI (F11.3) + Journal (F3.4, opt-in) + ctx-sys log audit (F7.3)
```

## Backpressure

Each subscriber has a per-task ring buffer of N events (default 1024). Slow subscribers (e.g. journal disk fsync) lag without blocking the bus; the TUI drops oldest events when the buffer wraps and shows a `… <K> lines truncated …` marker.

## Throttling

Token-by-token API output can produce thousands of events per second. The TUI debounces rendering at ~10 fps and concatenates streamed text within a debounce window into a single render. The underlying buffer keeps every event for log scrollback; only the rendered frame is throttled.

## ANSI Preservation

Agent output may contain ANSI escapes (Codex colored output, Claude Code's stream-json formatted text). The log pane preserves them; the renderer's wrap layer respects ANSI boundaries.

## Tool-use and Thinking Events

- `tool-use` events render as `▸ tool: <name>(<short-args>)` on a single line in the log pane, distinct color.
- `thinking` events render as dimmed italic prose in the log pane (and don't go to the journal by default).

## Selection Switching

When the user selects a different task, the log pane swaps to that task's buffer. Buffers for completed tasks are kept on disk in `.yaao/runs/<run-id>/<task-id>/output.log` (rotated with the run).

## Acceptance Criteria

- A 60-second-long task with continuous output renders smoothly without dropping the UI to <10 fps.
- Buffer overflow is annotated, not silent.
- ANSI from agent output renders correctly.
- Switching tasks during streaming is instant (< 50 ms perceived).
