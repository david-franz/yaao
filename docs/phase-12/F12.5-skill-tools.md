# F12.5 Skill-as-MCP-Tool Exposure

**Phase**: 12 — yaao-as-MCP (primary integration surface)
**Priority**: Critical
**Dependencies**: F8.1, F12.1

## Goal

Auto-register every skill in `.yaao/skills/<name>/` (and built-in skills) as a callable MCP tool `yaao_skill_<name>` on the yaao MCP server. This is what makes Phase 8's "thin per-agent stubs" workable: the heavy content lives behind one MCP boundary, not duplicated across four agent formats.

## Tool Shape

For a skill at `.yaao/skills/yaao-planner/`:

```typescript
{
  name: 'yaao_skill_yaao-planner',
  description: skill.skillYaml.description,
  inputSchema: deriveJsonSchema(skill.skillYaml.inputs),
  handler: async (input) => runSkillTool('yaao-planner', input)
}
```

`inputSchema` is derived from `skill.yaml.inputs` (declared name + required + default) — the same declarations that drive placeholder substitution in `prompt.md`.

## Tool Behavior

When an agent calls `yaao_skill_<name>`, yaao:

1. Loads the skill's `prompt.md` and substitutes input values into placeholders.
2. Returns the rendered prompt body as the MCP tool response, plus structured metadata:

```json
{
  "content": [{ "type": "text", "text": "<rendered prompt body>" }],
  "structuredContent": {
    "skill": "yaao-planner",
    "version": 1,
    "inputs": { "description": "...", "scope": "feature" }
  }
}
```

The agent then acts on the prompt body. yaao does **not** spawn a new agent or run the skill server-side — calling the tool is a way for the *calling* agent to fetch and apply a versioned, parameterized prompt.

## Why this design (and not server-side execution)?

Two alternatives were considered:

- **Server-side execution**: yaao spawns its own internal agent to run the skill and returns the result. Rejected — duplicates capability the calling agent already has, blows up auth/cost surface, and breaks the "the calling agent does the work" model that makes this composable.
- **Inline-only (no MCP exposure)**: every per-agent emitter inlines the full skill body. Rejected — that's the duplication-across-four-formats problem this phase is solving.

The chosen design — return the rendered prompt body as a tool response — is consistent with how callable MCP "prompts" or templates work in other ecosystems and is portable across all five agent backends.

## Hot Reload

F12.5 itself registers skills **once at server build**. Live re-registration when skills are added, removed, or modified mid-session is delivered by [F12.6](F12.6-skill-hot-reload.md) — a debounced FS watcher over the project + user skill roots that calls `reconcileSkillTools` on each change. The SDK auto-fires `notifications/tools/list_changed` on each register/remove, which is how Cursor, Claude Code, and Codex pick up the new catalog. (Older Copilot may need a reconnect.) See F12.6 for the implementation details, failure modes, and acceptance criteria.

## Built-in vs User Skills

- Built-in skills (`yaao-planner`, `yaao-converter`) are bundled in `dist/skills/` and registered at server start.
- User skills under `.yaao/skills/` and `~/.yaao/skills/` are discovered dynamically.
- Name collisions: project > user > built-in (matching the resolver from F8.1).

## Naming and Discoverability

`yaao_skill_<name>` is verbose by design — every yaao tool starts with `yaao_`, which keeps a single-namespace assumption and makes per-tool authorization rules trivial.

`yaao_plan` and `yaao_convert` (F12.2 / F12.3) are *not* registered via this mechanism — they're explicit tools backed by the planner/converter skills internally but with custom argument shapes (e.g. `yaao_plan` writes a file and returns the path; the raw skill tool just returns prompt text).

## Acceptance Criteria

- Built-in skills (`yaao-planner`, `yaao-converter`) are registered at server start.
- A skill present under `.yaao/skills/<name>/` when the server starts is callable as `yaao_skill_<name>`.
- Input schemas are valid JSON Schema and reject unknown fields.
- Calling the tool with valid inputs returns the rendered prompt body verbatim plus structured metadata.
- Project skills override built-ins on name collision.
- **Mid-session add/remove is delivered by [F12.6](F12.6-skill-hot-reload.md), not F12.5.**
