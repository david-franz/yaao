# F12.3 `convert_plan` MCP Tool

**Phase**: 12 — yaao-as-MCP
**Priority**: Medium
**Dependencies**: F12.1, F10.6

## Goal

Expose `yaao convert` as an MCP tool.

## Schema

```json
{
  "name": "convert_plan",
  "description": "Convert an implementation plan into an execution plan (YAML).",
  "inputSchema": {
    "type": "object",
    "properties": {
      "input":       { "type": "string", "description": "Path to the implementation plan." },
      "out":         { "type": "string" },
      "split":       { "type": "boolean", "default": false },
      "from":        { "type": "string", "enum": ["markdown", "speckit", "auto"], "default": "auto" },
      "inferDeps":   { "type": "string", "enum": ["off", "suggest", "auto"], "default": "off" },
      "agent":       { "type": "string" },
      "model":       { "type": "string" }
    },
    "required": ["input"]
  }
}
```

## Output

```json
{
  "ok": true,
  "files": [".yaao/exec/oauth.yaml"],
  "tasks": 9,
  "layers": 3,
  "agentsUsed": { "claude-code": 7, "cursor": 1, "codex": 1 },
  "warnings": [
    { "code": "YAAO_PLAN_FAN_OUT_HIGH", "message": "..." }
  ]
}
```

The `content` of the MCP response includes the full YAML so the parent agent can read it without a separate file fetch.

## Behavior

Mirrors `yaao convert` (F10.6). Validates after writing; returns warnings as structured data.

## ask_user Bridging

When the converter skill calls its `ask_user` tool internally, the MCP server bridges the question to the parent via `notifications/elicitation` (when the parent supports it) or auto-skips with a structured error if it doesn't. This lets a parent agent (e.g. Claude Desktop) surface the question to its user.

## Acceptance Criteria

- Round-trip via MCP: plan file → execution plan file → validates.
- `ask_user` bridging works with a parent that supports it; degrades gracefully otherwise.
- Warnings surface as structured items, not log noise.
