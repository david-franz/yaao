# F12.1 yaao MCP Server Scaffold

**Phase**: 12 — yaao-as-MCP
**Priority**: Medium
**Dependencies**: F1.3, F5.4, F9.5, F10.6

## Goal

Expose yaao itself as an MCP server. Any MCP-capable agent (Claude Desktop, Cursor, Codex, our own client) can drive yaao with the same fidelity as the CLI.

## Transport

```
yaao serve [--stdio | --socket <path>] [--http <addr>]
```

- `--stdio` (default): MCP over stdin/stdout. The standard for embedding into a parent agent.
- `--socket <path>`: Unix domain socket for long-lived attachments.
- `--http <addr>`: HTTP transport (for the web viewer; F14).

## Server Implementation

Built on `@modelcontextprotocol/sdk`'s server.

```typescript
// src/mcp/server.ts
export async function serve(opts: ServeOptions): Promise<void> {
  const server = new Server({ name: 'yaao', version: VERSION });
  registerTool(server, generatePlanTool);    // F12.2
  registerTool(server, convertPlanTool);     // F12.3
  registerTool(server, runPlanTool);         // F12.4
  registerTool(server, statusTool);          // F12.4
  registerTool(server, validatePlanTool);
  registerTool(server, listAgentsTool);
  registerTool(server, listPlansTool);
  // ... and a few read-only inspection tools
  await server.connect(makeTransport(opts));
}
```

## Tool Registration

Each tool has:
- A name (`generate_plan`, `convert_plan`, …).
- A JSON Schema for inputs (derived from the F2.1 / F1.3 Zod schemas).
- A handler that routes into the same code paths the CLI uses.

## Lifecycle / Concurrency

- One yaao MCP server per project.
- The server holds a single project context (config + cwd). Multi-project hosting is out of scope for v1.
- Long-running tools (`run_plan`) use MCP progress notifications for streaming updates.
- The server respects the `.yaao/.lock` for the run-related operations; concurrent `run_plan` calls within one server are queued.

## Authentication

- Stdio: trust the parent process.
- Socket: trust local FS permissions.
- HTTP: bind only to `127.0.0.1` by default; require a token (`yaao serve --http :PORT --token <t>`) for non-loopback binds.

## Error Surface

MCP tool errors map yaao's `YaaoError` codes into MCP error codes. The error message and hint are surfaced verbatim.

## Acceptance Criteria

- A simple MCP client connects via stdio, calls `tools/list`, and gets the expected toolset.
- The server serializes input validation errors in MCP format with `code` and message.
- Killing the parent process cleanly shuts down the server (no orphaned ctx-sys subprocesses).
